# 伙伴解剖修正原稿与 v7 正式包

七种角色的招呼、舒展、开心、行走共28组独立原稿由内置 ImageGen 生成。待机、环顾、休息沿用 `roster-v4` 的21组原稿；不再把四足动物的前腿、鸟翼和机器人手臂套用同一种抬手动作。

`prompts.json` 保存逐角色、逐动作提示词和实际参考路径；`corrections.json` 保存后续生成、选择与拒收记录。`*-candidate-*.png` 不参与构建。知羽开心的紧凑候选在第4帧保留了多余的胸前折翼，已拒收，正式源稿使用解剖正确的初次结果。

| 角色 | 身体约束与动作 |
| --- | --- |
| 微光 | 两前臂、两后腿、一个尾球；保留两个星簇 |
| 赤尾 | 四足狐狸；抬起原有前爪时移除对应地面前爪；舒展为俯身伸展 |
| 苔团 | 两枝手、两根脚；叶片和头顶芽不作为手脚 |
| 小栓 | 两条完整机械臂、两腿；天线固定在同侧，不能镜像换手 |
| 星角 | 四足、两翼、尾巴；招呼为点头，翼保持折叠 |
| 浪豆 | 两鳍、两脚；围巾末端仍为布料 |
| 知羽 | 两翼、两爪足；折在胸前的金色羽片是同一对翼，展开时原位置必须消失 |

行走原稿为8×4的32帧：转出4、起步4、循环16、收步4、转回4。其他新动作是4×3的12帧。分格、完整身体边距、RGBA、脚底和公共端点仍执行既有严格门禁。

```powershell
node tools/pixel/build-roster-actions.mjs
node tools/checks/check-companion-assets.mjs
```

先在 `staging/<species>` 完成全部七包检查，再写入 `frontend-shell/src/companion/packs/<species>-v7`。正式包共672张256px透明帧、35,918,359字节，`build-report.json` 保存各包缩放和体积。每角色统一缩放，以容纳最大完整动作；知羽因开心展翼缩放到0.831，不能为了增大形象裁掉翼尖。

普通回应12fps；步行保留16姿态，以12fps播放，一周期1.333秒、原生步幅48–60px。转身8fps。环顾转向帧160ms、两侧各停留1300ms。日常眨眼和轻呼吸持续，大动作间隔45–75秒，六次环境动作中只有一次舒展、一次走动。

格式与端点检查不能证明身体结构正确。正式素材对照和真实页面记录见 [v7复核](../../../docs/companion-anatomy-review.md)。
