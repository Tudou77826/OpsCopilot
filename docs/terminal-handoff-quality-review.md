# 终端接手原型代码审查

审查日期：2026-10-20。范围为固定场景的桌面终端接手链路，包括输入门控、运行协调、前端状态与隔离测试环境。

## 结论

原型保持了独立控制包、薄 Wails 适配和后端统一输入门控的结构。审查发现的日志锁与界面异步状态问题已修复，并增加确定性回归测试。可以继续作为后续应用能力接口的基础；当前结论不等于已经具备任意 AI 命令的授权、审计与通用 Shell 兼容能力。

## 发现与修复

| 优先级 | 问题及影响 | 修复 | 回归证据 |
|---|---|---|---|
| P1 | 生命周期日志回调位于服务锁内；慢回调阻塞停止，回调读取状态会死锁 | 回调移到锁外，启动日志前建立独立取消监听；日志之后发令仍校验操作权 | `TestAuditDoesNotHoldControlLock`、`TestCancellationReleasesOwnershipDuringAcceptedAudit`、`TestAuditMayReadStateAndStopBeforeDispatch` |
| P1 | 旧停止请求的迟到响应覆盖新轮次，界面会错误移除新占用遮罩 | 校验宿主、页面生命周期、本次操作及运行编号；保留已观测的新状态 | 前端“旧轮次的停止响应不能覆盖新轮次” |
| P2 | 页面离开时启动请求尚未返回，清理遗漏该轮；宿主更换也可能收到旧响应 | 页面离开使未完成操作失效；迟到启动仅停止返回的原轮次，不更新新页面 | 前端“页面离开期间启动才返回”“更换宿主后迟到的启动” |
| P2 | 启动返回的准备快照可能覆盖已收到的完成状态 | 同轮状态已由轮询观测时，保留该状态 | 前端“启动响应比完成状态晚到” |
| P2 | 取消后保留空闲确认，重新打开可沿用过时确认 | 打开、取消、断连或更换终端时重置确认；断连时隐藏测试表单 | 前端“取消后重新打开需要重新确认命令行空闲” |

前三类问题及确认残留均通过修复前失败的回归测试复现。补充的宿主切换、完成状态与取消监听用例用于覆盖相邻边界。

前端状态协调提取到 `useTerminalHandoff.ts`，与确认面板、遮罩呈现分开。隔离实验脚本清理继承的桌面预览环境变量，并在退出时恢复；页面验证脚本支持指定端口，在启动前拒绝占用端口，避免误操作其他预览。

## 继续推进前的边界

当前仅有两个固定只读场景及生命周期日志。接入真实 AI 前，仍需补齐逐次操作的授权、审批关联与实际执行审计，以及 AI 退出和等待提问的统一释放规则。任意交互程序、复杂提示符、后台输出的严格命令归属和全量会话生命周期并发不属于本轮验证结论。
