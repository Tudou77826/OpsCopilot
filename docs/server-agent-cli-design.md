# 服务端 Agent 的 Linux CLI 最小改造方案

状态：独立 CLI 已实现并完成工具侧自测；问题平台与目标内网的联合验收仍由集成方推进。适用于问题平台为每个问题启动独立 Chrys／iCode 会话，通过 OpsCopilot 访问业务服务器的场景。已实现调用方式见 [部署与调用](server-cli.md)，验证范围见 [自测记录](server-cli-validation.md)。

## 1. 职责与运行方式

问题平台管理问题、并发与排队、Chrys 进程、提问答复、会话恢复和结论回传。Chrys 负责理解问题、加载 Skill、运行发现／解密脚本、制定排查步骤和解释证据。OpsCopilot 提供独立 CLI，执行连接、命令、数据库查询、文件下载和知识检索。

第一版不引入 MCP 服务、常驻 Agent、工具侧任务队列、第二套模型自审或独立定位报告系统。

```text
问题平台 → Chrys／iCode → OpsCopilot CLI → 共用领域能力 → 业务节点／数据库
                  └──→ Skill／本地脚本：发现节点、解密或刷新凭据
```

远程操作限于只读定位，允许提权和访问本次任务所属业务环境内发现的节点。Chrys 负责判断和遵守操作边界，工具保留现有命令白名单、文件访问控制及数据库只读限制。白名单不构成任意 Shell 命令的只读证明，CLI 也不限制 Chrys 在工具外直接执行的本地程序；该执行权限由平台和 Chrys 的运行环境管理。

每次 CLI 调用是独立操作：建立所需连接，执行一次有边界的请求，返回后回收 SSH、数据库连接及 JDBC 子进程。目录、执行身份和数据库等条件必须在本次请求明确给出，不继承上次操作的 Shell 或事务状态。首版接受连接握手开销，连接复用不作为交付前置条件。

## 2. 共用代码与改动边界

| 位置 | 改造方式 |
|---|---|
| 新增 `cmd/opscopilot-cli` | 独立 Linux 入口，不导入 Wails、桌面 App 或前端资源 |
| 新增 `pkg/opscli` | 独立宿主的参数解析、请求转换和结果输出；复用领域服务，现有桌面 CLI 的参数与行为保持兼容 |
| 新增 `pkg/opssession` | 管理平台 Session 对应的节点配置、凭据引用、工作目录和关闭状态；不保存 Chrys 对话 |
| `pkg/core/ops` | 增加连接配置／凭据注入及稳定节点寻址，沿用白名单、输出裁剪和文件访问检查；修正状态、取消、重试和提权语义 |
| `pkg/remote`、`pkg/sshclient` | 复用密码认证、跳板和协议实现，补齐单次执行的 stderr、真实退出状态和有界输出收集 |
| `pkg/dbworkspace` | 复用驱动登记、连接、元数据查询、只读 SQL、超时与取消；用 Session 内配置和凭据存储装配 |
| `pkg/filetransfer` | 复用所需的传输实现与取消能力，不经过文件页签呈现和人工弹窗 |
| `pkg/knowledge` | 复用共享知识目录、索引解析和检索；只读调用不因索引缓存写入失败而伪装为空知识库 |
| 平台相关文件 | 将进程窗口设置按操作系统拆分，修复知识库等依赖的 Linux 编译；桌面更新器缺失的 Linux 实现单独处理，不成为独立 CLI 的依赖 |

桌面终端继续使用 `terminalcontrol` 对原 Shell 的接手、身份观察、占用与审计。数据库和文件页签继续由 `dbcontrol`、`filecontrol` 负责。服务端单次命令不冒充桌面终端接手，也不伪造页面回执。共用领域执行能力，保留两个宿主所需的不同生命周期与授权适配。

旧入口兼容：现有 `exec`、`file`、`knowledge` 的名称和可用参数继续保留。新的真实退出状态、stderr、独立执行和不自动重跑语义由 `opscopilot-cli` 提供，未将旧桌面配套 CLI 迁移为新宿主。旧 `diagnose` 仍是知识诊断入口，不把它包装成服务端自主定位，也不要求工具额外配置模型。

## 3. Session 数据与恢复

平台提供稳定且不含路径语义的 Session 标识，同一个问题恢复时沿用原标识。它与一次 Chrys 进程启动、一次 CLI 调用和一次数据库连接均不同。

部署配置提供独立的数据根、共享知识目录、驱动目录、Java 运行环境、策略文件和凭据存储所需密钥。每个 Session 在数据根下有独立目录，保存：

| 内容 | 保存规则 |
|---|---|
| 节点元信息 | 节点标识、类型、地址、端口、账号、访问路径、关联数据库与更新时间 |
| 凭据 | 与节点绑定的独立受保护存储；普通查询只返回是否已配置及凭据引用 |
| 工作文件 | 下载的文件、必要的任务输入；不把工作目录当作定位过程归档系统 |
| 生命周期 | Session 标识、配置版本、关闭状态；不持久化活动连接句柄 |

节点标识不能只使用 IP。同一主机的不同端口、账号和连接用途可以分别登记。凭据刷新默认更新原节点的凭据，不因刷新重算拓扑或更换节点标识；Skill 确认节点关系实际改变时再更新关系。

等待人工答复时，平台停止 Chrys 进程，工具释放活动资源，Session 数据继续保留。恢复时读取已有节点信息和凭据重新连接；凭据失效明确返回认证失败，由 Chrys 按 Skill 刷新，缺少资料再使用平台提问工具。OpsCopilot 不自行刷新、不强制平台重新提供全部信息。

Chrys 的定位思路、操作历史、问题和答案由平台与 Chrys 保存和恢复。是否能够原生恢复同一个 iCode Session 需要在联合验收中验证，不能用保留 OpsCopilot 节点目录代替模型上下文恢复。

凭据通过标准输入或受保护输入文件交接，不设计密码命令行参数，不在普通结果和错误中回显。服务端实现 `SecretStore` 的 Session 存储适配，凭据加密落盘，解密密钥由部署配置提供并置于 Session 数据之外；不强制依赖桌面 Keyring。目录采用属主访问权限，写入复用现有跨进程文件事务，防止部分写入和更新覆盖。

同一服务账号下的 Session 隔离用于防止误操作和数据串用，不宣称是对恶意本地代码的操作系统沙箱。Chrys／平台自身的上下文、工具输入及日志中的凭据处理属于其保存策略，工具只能保证自身不额外回显或拼入命令参数。

只有平台明确关闭 Session 才清理其中的凭据和临时文件；停止一轮执行、异常退出、凭据过期均不自动删除 Session。关闭时阻止新调用、取消已登记的活动调用并等待有界收尾，再清理数据；不能确认远端停止时如实返回。重复关闭幂等，旧调用不能重新写回关闭后的 Session；同一标识不能隐式复活。平台负责决定定位历史的保留周期。

## 4. CLI 能力与返回约定

以下能力已具备对应实现，命令和参数以 [部署与调用](server-cli.md) 和服务器 Skill 为准。数据库强制只读事务当前限已适配的 MySQL 方言，通用 JDBC 明确拒绝；下载首版使用 SFTP。

| 能力 | 请求内容 | 返回内容与行为 |
|---|---|---|
| Session 初始化／检查／关闭 | 平台 Session 标识、部署允许的任务元信息 | 初始化或读取 Session，关闭时清理工具侧数据；不启动 Agent |
| 节点登记／更新／列表 | SSH 或数据库节点信息、完整跳板路径、凭据或引用 | 稳定节点标识、脱敏摘要；支持脚本通过标准输入提交结果 |
| 远程命令 | Session、节点、命令、目录、执行身份、意图、超时 | 独立执行，返回 stdout、stderr、真实退出状态及截断信息 |
| 数据库驱动与结构查询 | 部署驱动标识、数据库节点、库或表 | 返回可用驱动、库表和结构；不动态下载或安装驱动 |
| 只读 SQL | 数据库节点、SQL、目标库、行数与超时上限 | 使用既有只读限制与驱动能力，返回结构化结果及明确截断标记；不保留跨调用事务 |
| 文件下载 | SSH 节点、远端文件、Session 内落地位置、大小限制 | 完成或失败、实际路径及是否存在部分文件；Chrys 可用原生工具分析 |
| 知识检索 | 现有 `knowledge list/search/read` 参数 | 查询部署时准备的共享知识库，不按 Session 复制或重新维护知识 |

服务器工具范围不包含桌面页签操作、远端修改／上传安装、交互式 TUI、问题平台的提问与结论回传。原有桌面及旧 CLI 的其他功能不因服务器范围收窄而被删除。

提权在单次请求明确指定目标身份及方式，使用当前 Session 保存的凭据。独立命令执行采用 stdin 传递提权密码，不在提权失败后偷偷改用普通身份执行，也不自动重跑命令。文件通道具有自己的访问身份，不能因为上次命令使用 `su` 就宣称后续 SFTP 已提权；不满足读取权限时返回真实错误。

输出继续采用现有 CLI 的大小与长行裁剪规则，显式返回截断标记、已知字节／行数及裁剪原因。收集阶段也设置有界缓冲，不能先无限读入内存再截断。若因缓冲上限无法确定输出总量，不捏造总数。数据库行数裁剪同样明确标记。工具不保存完整输出供另一个读取接口使用；Chrys 自行缩小远端查询范围，或按需明确下载文件分析。

stdout 输出可机器读取的结果，stderr 用于必要诊断且过滤凭据。结果区分成功、操作失败、策略拒绝、认证失败、超时、取消、结果未知和工具内部失败；CLI 退出状态与成功／失败结果一致。已有退出码按原值返回，不能确认时返回未知，不能统一伪造为远端退出码 1。

断线、超时或取消后，返回已收到的输出、已知执行阶段和停止确认状态，不自动重连重跑、不降级身份重试、不把关闭客户端通道当作远端进程已停止。平台通过正常终止信号取消 CLI 时，取消向下传递并有界回收资源；强制杀进程和主机崩溃无法保证远端已停止，恢复后由 Chrys 核对现场。

操作记录依赖 Chrys 的工具轨迹；工具不增加第二份命令、SQL 或原始输出归档。结果中的节点、状态和耗时足以由 Chrys 关联本次调用。桌面原有审计保持原职责，不因服务器采用 Chrys 轨迹而被移除。

平台负责启动数量与排队。工具仅串行保护同一 Session 的配置更新、关闭与必要资源登记，不持有覆盖整个远程执行期间的全局锁，不建立跨问题任务队列。

## 5. 实施顺序与阶段验收

每步完成代码、针对性测试和相关 Skill／使用说明同步后再进入下一步。第一版包括 SSH、数据库、下载和知识能力，不将仅有 SSH 的中间版本称为完整交付。

| 阶段 | 交付内容 | 主要验收 |
|---|---|---|
| 1. 独立入口与 Linux 底座 | 提取共用 CLI 适配，独立构建；修复所需平台依赖；保留旧命令 | Linux 无图形环境执行帮助与知识查询，所需包无 Wails 依赖；Windows 桌面与 CLI 回归通过 |
| 2. Session 与 SSH | 节点／凭据跨进程保存、跳板、独立命令、提权、精确状态、输出裁剪与取消 | 进程退出后恢复节点和凭据；多账号／端口不混用；不重跑、不改身份重试；拒绝及失败不会伪装成功 |
| 3. 数据库与文件 | 部署驱动查询、Session 内数据库配置、只读 SQL、元数据、下载 | Linux Java／JDBC 实际连通；SQL 与文件输出有界；查询与下载取消后收尾，部分结果明确 |
| 4. 平台与 Chrys 联合验证 | 服务器 Skill 和调用契约、暂停／恢复／关闭、部署说明与构建产物 | 使用实际 Chrys／iCode 和测试问题平台，完成下述全链路；并在目标内网复测 |

阶段 2 先形成 SSH 与 Session 的技术闭环，可提前暴露协议及持久化问题；不把新认证方式、MCP、常驻连接池或自建模型审查加入这一阶段。

最小全链路验收场景：

1. 平台创建 Session 并提供管理节点，Chrys 按 Skill 发现业务与数据库节点，登记后执行日志和只读 SQL 检查。
2. 结果超长时收到明确截断标记，Chrys 通过更窄查询取得需要的证据，不依赖隐藏的完整结果归档。
3. Chrys 向平台提问后退出；无 SSH、JDBC 活动资源残留，Session 节点、凭据与下载文件仍存在。
4. 用户补充后启动新进程，恢复原定位上下文并直接使用原节点，不重复发现拓扑；让一份凭据失效，验证 Chrys 仅刷新该凭据后继续。
5. 同时运行两个问题，验证连接、凭据更新及文件路径不串用；取消其中一个，不影响另一个。
6. 注入断线、提权失败和超时，确认每次请求不隐藏重跑，结果说明实际执行和停止的已知程度。
7. 平台关闭其中一个 Session，验证活动调用有界停止、凭据和临时文件清理、迟到调用不能复活，其他 Session 保持可用。
8. 核对 Chrys 工具轨迹能够追溯实际调用与结果，工具没有新增全量输出归档，最终结论由平台接收。

Linux 交叉编译只能证明编译兼容，测试替身只能证明接口行为。目标 Linux 实机、实际 JDBC 驱动、内网跳板和 Chrys 跨进程恢复分别记录验证结果，不以其中一项替代其他项。

## 6. 实现依据

- [现有 CLI](../cli.go)：命令分派、环境路径、固定输出预算和按次关闭连接管理器。
- [非交互运维内核](../pkg/core/ops/manager.go)、[命令执行](../pkg/core/ops/exec.go)：连接／凭据装配、白名单、重试和提权逻辑。
- [远程协议接口](../pkg/remote/connection.go)、[SSH 执行](../pkg/sshclient/client.go)：单次命令与交互 Shell 的不同接口、执行取消和输出收集。
- [数据库领域服务](../pkg/dbworkspace/service.go)：独立连接、查询、只读事务和取消；不依赖数据库页签。
- [桌面工作台呈现](../pkg/workspace/service.go)：页面心跳和呈现回执属于桌面宿主边界。
- [统一应用架构](application-kernel-architecture.md)：共用领域能力与宿主适配原则；其中的页签占用、单 AI 执行序列适用于桌面进程，不扩展为服务端平台的全局串行限制。
