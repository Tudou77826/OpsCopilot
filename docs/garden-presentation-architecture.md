# 养成内容包与呈现运行时

> 状态：冻结实现的维护规范，内容包契约 v2 / 呈现运行时 v2。功能默认关闭；不推进新内容包和后续迭代。启停规则见上位设计。
>
> 适用范围：OpsCopilot 桌面端与 Teams 插件共用的养成呈现能力
>
> 上位设计：[OpsCopilot 养成与收藏系统设计](cultivation-system-design.md)

## 1. 架构边界

成长状态和内容呈现是两个独立边界：

- Go 状态层保存货币、收藏实例、等级、经验、品质和用户布局；
- 内容包声明场景、素材、元素文案、放置约束和动作资源；
- 通用呈现运行时读取状态快照与一个内容包，生成画面；
- 桌面端与 Teams 插件只提供宿主入口和通信适配，不解释内容包。

运行时不按植物、动物或建筑分派渲染器。题材变化只能来自清单和静态资源，不能要求新增题材专属组件。

## 2. 包目录

内置包采用以下结构：

```text
packs/<pack-id>/
  manifest.json
  index.ts
  assets/
```

- `manifest.json` 是纯 JSON 清单，不允许函数、脚本、动态库或 CSS；
- `assets/` 只存放清单声明的 PNG/WebP；
- `index.ts` 只把构建器生成的资源 URL 注入清单，不包含元素特例和渲染逻辑。

## 3. 契约组成

### 3.1 身份与兼容性

每个包必须声明：

- `contractVersion`：内容包契约版本；
- `id` 与语义化 `version`；
- `runtime.min/max`：支持的呈现运行时版本；
- `stateSchema.min/max`：支持的成长快照 schema；
- 名称、作者、题材文案和六个阶段名称。

运行时或状态版本不兼容时必须明确失败，不允许切换到其他内容包继续显示。

### 3.2 资源

`assets` 为资源注册表。每项声明包内相对路径、类型、字节数、宽度和高度。元素与场景只引用资源 id，不直接拼接路径。

当前资源类型：

- `image`：场景、阶段形象、装饰或帧序列中的单帧；
- `sprite-sheet`：动作精灵图集。

清单路径不能越出包目录。构建门禁会读取真实文件，核对字节数、图片尺寸和资源预算。

### 3.3 场景

场景声明昼夜背景、宽高比、安全显示区域、缩放方式、活动区域、层级参考格位、装饰物和夜景参数。

坐标、尺寸与活动区域统一使用 `0–1` 归一化坐标。面板尺寸改变时，内容包不依赖固定像素位置。

活动区域目前允许 `ground`、`air` 和 `water`。为了保证线性路径始终留在边界内，v2 要求活动区域是面积充足的凸多边形。用户保存的归一化落点必须位于元素所属区域；格位只提供兼容性和图层参考，不再自动决定收藏排列。水域可以进入清单，但对应移动行为只有在运行时提供通用原语后才能启用。

### 3.4 收藏元素

每个元素声明：

- 名称、含义和说明；
- 可选的价格、分类与购买初始等级；
- 六阶段普通素材，可选六阶段闪光素材和成熟姿态变体；
- 归一化锚点、点击区域、默认尺寸和可选的六阶段尺寸系数；
- 可选的元素级六阶段文案；
- 放置类型、活动区域和层级；
- 动作片段；
- 动作时长、权重、速度和避让半径等行为参数；
- 减少动态效果时的静态资源。

内容包可以只收录状态目录的一部分元素。未收录元素不会跨包回退，界面会明确显示未被当前包收录的数量。元素的视觉尺寸归元素自身的 `defaultSize`，不得借用某个格位的尺寸，否则自由布局时会因购买顺序改变大小。

## 4. 动作资源

动作名称固定为 `idle`、`move`、`eat`、`sleep`、`hop`、`fly` 和 `react`。内容包可以声明其中任意子集。

动作片段支持：

- `procedural`：使用运行时内建动作原语；v2 提供轻微 `sway` 与显示当前阶段素材的静态 `still`；
- `sprite-sheet`：声明图集、单帧尺寸、行列、帧数、帧率、循环、静态替代帧和可选水平翻转；
- `frame-sequence`：声明有序资源列表、帧率、循环和静态替代帧。

动作素材与行为参数分离。每个自主动作显式声明时长区间和权重；移动元素还必须声明速度区间与避让半径。运行时不会根据题材或元素 id 推断行为。

### 4.1 像素美术声明

正式内容包通过 `art` 声明像素美术规格。当前生产规格为 `style: pixel`、主体 `64×64px`、昼夜场景 `960×320px`。构建门禁要求主体素材为 `64×64px`、图集可被单帧尺寸整除。

像素数不决定观感，**绘制源的信息量**才决定观感：同样是 `64×64`，程序化拼出的色块放大后是糊状颗粒，手绘稿缩到 `64×64` 仍保留形状与明暗。所以约束落在流程上——素材必须来自绘制，并经过固定配方归一化。

显示：主体在面板里约以 `120px` 呈现，是刻意的约 2 倍最近邻放大。`image-rendering: pixelated` 保持像素边缘；希望每个素材像素等宽时，显示尺寸取素材边长的整数倍（`64×64` 对应 `128px`）。

基础网格不作为素材分辨率的约束；场景内的区域、格位与锚点继续使用归一化坐标。

该声明只影响养成内容，不改变工作台控件。元素级阶段文案和尺寸系数用于让植物、动物与建筑在同一主题中自然成长，不改变状态层等级规则。

四种放置类型的运行语义为：

- `anchored`：固定在格位，不执行路径移动；
- `ambient`：固定在格位，可以执行待机、进食、睡眠或回应动作；
- `ground-roaming`：在 `ground` 区域内执行 `move` 或 `hop`；
- `air-roaming`：在 `air` 区域内执行 `fly`。

通用状态机按内容包权重选择动作，按时长切换状态，并遵循动作片段声明的 `next`。移动目标、速度和动作序列由实例稳定种子产生；运行时计算朝向、区域边界、纵深层级和同区域基础避让。位置、动作、朝向和帧号都不写入成长存档。

精灵图集与帧序列由同一播放器按声明帧率推进。非循环片段停在最后一帧，减少动态效果时固定到 `reducedMotion` 资源或图集静态帧。点击元素可以触发 `react`，随后按动作声明返回自主状态。

### 4.2 素材生产与归一化

美术素材靠**绘制**产出，不由程序合成形象。绘制源可以是手绘，也可以是绘图 AI；仓库保存绘制结果并留档绘制源，便于后续按同一风格补画新元素。

程序只参与**一轮归一化**，配方逐项固定，这是"统一观感"真正落地的地方：

| 步骤 | 取值 |
|---|---|
| 源图预缩 | 缩到原尺寸的 `50%`，先压掉细节噪声 |
| 源图预量化 | 把源图量化到约 `24` 色，再进入降采样（实测 24 色最干净，给到 32 色以上反而回噪） |
| 采样 | 众数（每格取出现次数最多的颜色） |
| 去背景 | 四角取色抠图，容差 `36` |
| Alpha | 阈值 `128` 并二值化，边缘不留半透明 |
| 调色板 | 量化到 `96` 色 |
| 抖动 | 无 |
| 描边 | 自动加深，宽度 `1px`，加深系数 `60%` |
| 输出 | `64×64` |

`64×64` 由约 `384` 像素见方的一格缩减而来，比例约 `6:1`，每格只落十来个源像素。把源图先量化到 `24` 色左右，格内颜色才有主次，叶子色块更平整；给到 `32` 色以上反而回噪，因为每格又开始在过多近似色之间乱挑。画面里的点缀同理不宜多而小——孢子、金边、粒子一旦密度过高，缩减后是斑块和噪点，不是精致的细节；金饰只应出现在最外轮廓与奖励部件上。

归一化不得改变形象本身：不得用放大结果替代更精细的绘制，不得新增或删除形状。可验证的判据是——把归一化后的图与绘制源并排看，轮廓一致；调色板与边缘的差异属于归一化的允许范围。

描边用"自动加深"会为每个描边像素派生一个新颜色，实测 `96` 色配自动描边最终约 `160–170` 色。如果整包要严格共用一个 `96` 色调色板，描边色需改为从调色板取值（例如取最深一档），不能按像素各自派生。

素材交付契约，绘制方按此产出：

| 项 | 要求 |
|---|---|
| 交付尺寸 | 主体 `64×64`；昼夜场景 `960×320`（3:1，尺寸待复核） |
| 绘制源 | 尺寸不设上限，建议至少 `512×512` |
| 背景 | 透明，或使用单一纯色底（由四角取色抠除） |
| 锚点 | 锚点、接地点和活动区域用归一化坐标，与分辨率无关 |
| 阶段素材 | 每个元素 6 个阶段，普通与闪光各一套 |
| 动作图集 | 单帧 `64×64` 横向排列，帧数与帧率按动作声明 |
| 命名 | 沿用现有约定：`<前缀>-<阶段>.png`、`<前缀>-<阶段>-shiny.png`、`<前缀>-<动作>.png` |

构建门禁相应按管线校验，替代原先按固定网格值硬比对的做法：主体素材尺寸等于声明值；图集可被单帧尺寸整除；整包调色板色数不超过共用调色板上限。

首套正式主题为**丘陵植物志**：六个槽位都是原地生长的植物与菌类（命令薄荷、传输蕨、守护兰、知识橡树、会话菌、脚本藤），
草地丘陵昼夜双景，素材共 `110` 张（6 元素 × 2 品质 × 9 格 + 昼夜场景两张），构建门禁当前报告约 `313 KB`。
每件收藏的九宫格第 6–9 格对应契约的成熟变体池：同一成熟阶段会按个体 ID 哈希在四个变体里选用，
不同个体的成熟形态因此略有差异。

全部素材的一览见 `docs/assets/garden-asset-sheet.png`，场景在游戏内显示尺寸下的效果见 `docs/assets/garden-scene-preview.png`。

绘图提示词由 `frontend-shell/garden-art-prompts.html` 生成：骨架（画布、网格、画风、交付规则）固定不变，主题（元素外观、六阶段演化、配色、场景与昼夜）由使用者填写，产出按素材拆分的固定像素九宫格提示词。调参页见 `frontend-shell/garden-art-tuner.html`，两者与本节配方保持一致，改配方时三处同步。

## 5. 季节与节日覆盖

覆盖包可以替换：

- 昼夜背景、环境装饰与夜景参数；
- 元素名称、说明、六阶段素材、闪光素材和静态替代资源。

覆盖包必须声明适用的基础包，不得添加或修改成长通道、等级、经验、概率和排行数据。覆盖包资源 id 不得与基础包冲突；目标元素必须已经存在于基础包。组合结果会再次经过完整包校验，并记录已应用的覆盖包 id。

## 6. 校验与预算

运行时登记前检查：

- 契约、运行时和状态版本；
- id、语义化版本、六阶段文案与必填字段；
- 场景区域、层级、格位、锚点和点击区域；
- 活动区域凸性、格位归属、移动类型与区域类型；
- 所有资源引用与资源类型；
- 动作名称、帧率、帧数、图集网格和静态帧；
- 动作时长、权重、移动速度和避让半径；
- 清单只包含普通 JSON 数据；
- 同 id 内容包不得静默覆盖。

构建门禁检查真实文件：

- 普通图片不超过 2MB；
- 动画图集不超过 4MB；
- 单包资源总量不超过 12MB；
- 单动作不超过 120 帧，帧率不超过 24fps；
- 图集行列和单帧尺寸不能超出真实图片边界；
- 清单声明的字节数和尺寸必须与文件一致。

实测 `64×64` 主体归一化后约 `6–8KB`：按 72 张阶段素材（6 元素 × 6 阶段 × 普通/闪光）估算约 `0.5MB`，加上动作图集与昼夜场景后仍在 `1MB` 量级。上述预算是上限而非目标值，全套素材就位后需按实测重新确定单主体、单图集与单包总量，并确认插件包体积上限的具体数值——插件把资源内联进 `ui.js`，内联后的体积是本包资源总量之外的另一笔开销。

桌面共享前端和 Teams 插件构建都会执行 `tools/checks/check-garden-assets.mjs`。

## 7. 运行生命周期与性能

- 场景面板关闭时不挂载场景组件，因此不加载图片、不创建状态机和动画调度器；
- 页面进入隐藏状态时取消动画帧调度，重新可见后从当前时刻继续，不补算隐藏期间的时间；
- 系统启用“减少动态效果”时不创建动画调度器，移动元素回到格位并使用静态替代资源；
- 动作素材只在对应动作实际呈现时进入图片解码路径；
- 运行时最高以 24fps 提交画面，同屏最多 12 个活动元素，超出部分保持静态；
- 场景宽度至少填满停靠区域；窄面板在保持内容包宽高比时允许横向游览。

## 8. 当前实现

- 契约与校验：`frontend-shell/src/ui/garden/contentPack.ts`；
- 状态适配、资源解析与注册表：`frontend-shell/src/ui/garden/pack.ts`；
- 通用场景：`frontend-shell/src/ui/garden/ContentGardenScene.tsx`；
- 动态状态机与几何计算：`frontend-shell/src/ui/garden/gardenRuntime.ts`；
- 动画生命周期调度：`frontend-shell/src/ui/garden/useGardenRuntime.ts`；
- 通用元素与帧播放器：`frontend-shell/src/ui/garden/GardenActor.tsx`；
- 官方内容包：`frontend-shell/src/ui/garden/packs/botanical/manifest.json`；
- 资源构建门禁：`tools/checks/check-garden-assets.mjs`。

官方植物绘本包当前收录已有完整文件的薄荷、蕨和兰花。会话杉、脚本藤和知识树尚无合格美术资源，因此没有用占位图或旧 SVG 路径补齐。

契约测试同时构造纯数据动物包和建筑包。两者通过同一个场景组件完成装载，用于防止后续代码重新引入题材分支。运行时测试覆盖区域移动、进食、休息、点击回应、精灵图与帧序列、同屏预算以及隐藏和减少动态效果下的调度停止。
