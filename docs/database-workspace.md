# 数据库工作区

数据库入口位于主窗口右侧导航栏。点击后在主区域打开数据库标签，可与终端、文件传输切换和分屏。数据库连接统一使用用户导入的 JDBC 驱动，不内置厂商数据库驱动。完整离线包包含私有 Java 运行组件。MySQL 提供专用方言；Gauss 100 使用通用 JDBC 能力，已在一个内网环境完成连接和查询验证，其他版本与操作仍需分别验收。

## 使用

首次使用先导入厂商 JDBC JAR；导入成功自动返回连接表单并选中新驱动。Gauss 100 预填驱动类和 `jdbc:zenith:@{host}:{port}`，MySQL 预填 Connector/J 配置；驱动类与模板收在“高级驱动设置”。新建连接且只有一个已导入驱动时自动选中，端口仍需按实际数据库填写。随后在“数据库”页填写地址、端口、用户名、密码和可选的数据库。“SSH 隧道”页配置跳板机；“更多设置”页配置名称、连接标记、分组、TLS 和可选的只读限制。连接名称默认自动生成；连接标记显示在名称旁，仅用于区分生产、测试等环境，不改变连接或账号权限。测试连接直接验证当前草稿，不保存配置或凭据，不改变已有查询会话；成功后可选择仅保存或保存并连接。

SSH 隧道可以选择已保存的 SSH 连接，使用后台独立连接，不占用交互式终端。JDBC 使用仅监听本机回环地址、随会话回收的临时转发端口。关联节点的凭据需已通过会话管理保存。

用户只需选择已保存的最终 SSH 节点，程序内部处理逐跳连接，不展示完整跳转路径或通道模式开关。数据库地址从该最终节点的视角填写；数据库仅监听该节点回环时使用 `127.0.0.1`。程序优先使用标准转发，只有 SSH 返回明确的策略拒绝（`ssh.Prohibited`）才自动尝试同账号、同目标的远程命令通道。连接被拒绝、超时及数据库认证错误不会触发该切换；SQL 不自动重试。旧版本显式保存的命令模式仍可读取，在表单保存后统一采用自动策略。

兼容模式要求最后一台节点可执行 Python 3 标准库脚本并访问目标端口，不上传脚本文件、不创建远端监听端口、不安装常驻服务或远端 JRE。远端 TCP 建立后返回随机标识绑定的就绪帧，再传递数据库数据；错误状态与数据分离，不把启动命令成功等同于数据库 TCP 建立。每个连接对应一个临时进程，每方向仅保留有限数据块，启动最多 10 秒并受连接操作剩余时间约束。主动关闭尝试终止远端进程并关闭 SSH 通道；输入 EOF 后在空闲 10 秒内结束响应排空，限制异常断开后的进程存活。活动查询不设置此空闲超时；查询超时和取消继续由数据库服务控制。SSH 通道不支持 socket deadline，使用现有操作 context 和连接关闭控制生命周期。

JDBC 建连失败时，错误详情包含“连接诊断 v2”标记、连接方式、驱动类与版本。SSH 模式还显示最终 SSH 节点视角的目标、本机接入次数、远端 TCP 通道建立次数、双向累计转发字节数和首先结束的转发方向，并保留通道建立及转发读写异常。诊断在主动关闭连接前取样，不记录报文内容；字节数是取样时已成功写入的累计量。TCP 通道建立不代表数据库握手或认证成功，仅有本机转发端口的 `Connection reset` 也不能证明数据库已收到连接。

每次通过配置校验并取得凭据后的“测试连接”和“连接”还生成独立的“数据库连接诊断 v4”报告，保存在配置目录下的 `database-diagnostics/connection-<时间>-<编号>.log`，仅保留最近 20 份。默认配置目录在程序旁；成功连接也生成报告。失败详情附带报告和保存路径，使用现有复制入口即可复制。目录不可写时保留界面报告，不改变连接成败，也不覆盖原始错误。

报告按结果与失败阶段、原始异常、固定对照字段、证据判断、针对性核对项及时间线组织。对照字段包含 Java 构建、厂商、架构、实际堆上限、JVM 收到的数值型内存参数及直接内存限额来源；组件指纹覆盖 Java 启动器、JVM 本体、发行信息、辅助程序和已校验的驱动 JAR。读取指纹失败只标记字段缺失，不改变连接结果。成功连接记录已读取的数据库产品与版本；失败前未取得的信息明确标为未知。

JVM 内存限额优先从可用的管理接口读取，否则只解析 JVM 收到的明确启动参数，并标明来源；自动限额不推算为确定值。`JAVA_TOOL_OPTIONS`、`JDK_JAVA_OPTIONS`、`_JAVA_OPTIONS` 只记录是否存在，不输出值或完整 JVM 参数。Java 启动前的标准错误只匹配固定的失败分类，不原样输出可能含密钥的环境变量。旧辅助程序未提供新字段时继续连接，报告注明未采集。诊断正文最多 64 KiB，达到上限时明确标记截断并保留有效 UTF-8。

报告记录应用版本、实际配置的 SSH 路径、节点账号、认证尝试、服务版本、主机密钥指纹、跳转时的通道方式、最终数据库通道模式，以及 JDBC 驱动 JAR 校验值、私有 Java 版本、过滤凭据后的 URL、实际应用的属性和连接/版本读取阶段。标准模式记录 `direct-tcpip` 的返回原因码；兼容模式记录 Python 启动、远端 TCP 就绪或结构化失败状态。SSH 跳转原有的远程命令备用路径如被触发会单独标记，该路径具体执行了哪个候选工具仍未知。标准转发被明确拒绝时的自动兼容尝试单独记录；不改换目标或账号。Go 时间线记录事件观察时间；Java 阶段在 RPC 返回时回传，另附请求内耗时。报告区分已确认事实和待验证假设，不把策略拒绝等同于某个已知的服务器配置项。

诊断不额外执行网络探测、远程命令或 SQL；兼容模式运行的远端脚本属于实际数据通道。程序不尝试其他账号，不记录密码、SQL、查询结果和报文内容。报告包含内网地址、SSH 账号和主机指纹，分享时应按环境要求处理。对照不同目标地址时，每次只修改一个配置项并分别测试，保留对应日志编号；不要同时修改 SSH 路径、数据库地址与驱动。没有读取服务器策略、抓包或成功软件的执行日志时，不能仅凭客户端日志确认策略来源或其他软件采用的通道机制。

## JDBC 驱动

完整离线包包含 `jdbc-runtime/`；基础应用包需另行放置该组件才能使用数据库功能。不依赖系统安装的 Java，不设置全局 JAVA_HOME，JVM 仅在导入验证和建立 JDBC 连接时按需启动。旧原生 MySQL 连接配置及凭据保留，编辑时需明确选择导入的驱动；不会将旧连接静默绑定到其他厂商驱动。

在添加或编辑连接中点击“管理驱动”，选择驱动类型及厂商 JAR、依赖文件后导入；非预设驱动需在高级设置中填写驱动类和 URL 模板。MySQL 已预填 `com.mysql.cj.jdbc.Driver` 和 `jdbc:mysql://{host}:{port}/{database}`。导入会校验文件、尝试加载驱动类，并将 JAR 复制到配置目录的 `jdbc-drivers/<id>/`；原文件移动后不影响使用。每个 JAR 上限 64 MiB，最多 8 个，总计不超过 128 MiB。后续加载核对 SHA-256；被连接引用的驱动不能移除。JAR 是可执行代码，应使用可信厂商分发版本；辅助进程隔离不等于权限沙箱。

选择导入的驱动后，仍填写地址、端口、账号、密码和数据库。账号密码通过私有标准输入传递，既不写入 URL 模板，也不放进进程命令行。导入时用样例地址调用驱动的 `acceptsURL` 检查模板，实际连接前再次检查生成的 URL；校验通过不代表网络、认证或版本兼容性已经通过。

连接错误包含失败阶段、SQLState、厂商代码和有长度上限的异常原因链。驱动异常文本显示前移除数据库账号、密码、密码参数及原始 JDBC URL，SQL 执行错误中的字符串常量也会隐藏。连接表单及工作区错误旁可直接复制错误详情；连接诊断报告额外包含上述经过过滤的连接元数据。Java 标准输出和标准错误不作为驱动日志暴露给前端。

Java 运行组件随包带上 JAXB 2.x／Activation API 的 `javax.xml.bind` 和 `javax.activation` 兼容类，供依赖 Java 8 API 的旧驱动使用。这不等同于保证所有旧驱动都能在 Java 21 上运行；缺失其他类、Java 版本不匹配及握手失败分别给出对应诊断。

MySQL JDBC 支持现有查询、表浏览、字段、索引、DDL、SQL 模板、服务端只读事务和查询取消。通用 JDBC 提供连接、查询、标准库表字段索引元数据和 ANSI 分页；DDL 与写入模板、数据库特有语法需要方言适配。通用模式不提供程序强制只读或 TLS 参数映射，建议使用数据库只读账号；不能将导入成功视为 Gauss 100 兼容性验收。MySQL JDBC 的 TLS 使用 Java 运行组件信任库；经 SSH 的证书主机名校验尚未支持，程序会明确拒绝该组合。

MySQL 的 `caching_sha2_password` 在没有 TLS 且需要完整认证时可能要求获取服务器 RSA 公钥。“更多设置”页提供显式选项，默认关闭，仅在受信任的网络或 SSH 通道内启用；不作为连接失败后的自动降级。

每个 JDBC 物理连接使用一个独立、按需启动的 Java 辅助进程，驱动版本互不混用，最多同时打开 4 个。每进程默认请求 16–96 MiB Java 堆；环境注入参数可能改变实际值，以 JVM 返回的上限为准。实际进程内存还包括直接内存、JVM、线程和驱动开销。关闭连接、停止、超时或进程异常后释放辅助进程；SQL 不自动重试。取消通过独立控制线程调用 `Statement.cancel()`，随后关闭辅助进程和连接。不同驱动对取消的服务端效果不同，需在目标环境验证。

正常启动不显式设置直接内存上限，保留 JVM 原有策略，避免诊断改变环境差异。先在成功、失败环境正常启动同一版本，各采集一份报告。需要单变量对照时，再通过当前进程的 `OPSCOPILOT_JDBC_DIRECT_MEMORY_MB` 请求 16–1024 MiB，或使用 Windows 包中的 `jdbc-memory-check.cmd` 选择显式 96 MiB／1024 MiB；无效值会在启动组件前拒绝。入口不改变堆参数请求，关闭程序后失效。必须保持其他连接配置相同，不能仅因一次超大缓冲申请便认定应长期提高上限；多个连接的直接内存占用分别计算。JVM 异常提供明确限额时，报告以该次异常数字作为额外证据。

内存分配失败时保留原始异常和申请／已分配／上限数字；驱动保留原始 `OutOfMemoryError` 时额外采样最多八个类、方法和行号，兼顾栈顶及驱动调用位置，不包含文件路径、参数或报文。仅有异常字符串时明确缺少原始分配栈，外层异常调用位置单独标识。其他建连失败也保留受限调用位置。宿主回收发生内存错误的辅助进程，不自动扩大内存或重试查询。

辅助程序是一个 Java 21 小程序，通过有长度上限的 stdio JSON 协议通信，没有 Java Web 服务、ORM 或监听端口。Go 的 `database/sql/driver` 适配层接入现有 `Connector`，生产服务仅注册导入的 JDBC 适配器，原生 MySQL 连接实现仅保留在测试文件中。继续复用会话串行控制、凭据库和工作区接口。结果按文本和 NULL 传递；二进制单元格显示为十六进制。Java 端也限制行数、列数和单元格／总字节数，超过字节界限明确失败；脚本的语句识别和顺序执行统一在 Go 端处理。一次存储过程调用返回的多个结果集尚未适配。

构建组件使用 Java 21 JDK、Maven 和 `./build/jdbc/build.ps1`，输出目录必须不存在。脚本用 jlink 保留 SQL、命名、管理、网络及安全相关模块，保留运行时许可证。新厂商驱动如依赖其他 JDK 模块或原生库，仍需补充运行组件后验证。发行流水线分别生成基础包、JDBC 组件包与完整离线包；厂商驱动不随发行包分发。

Windows 本地完整打包使用根目录 `build_release_jdbc.bat`，需要 Go、Node.js、Wails、Maven 和 Windows x64 Java 21 JDK。双击或从任意工作目录运行均可；可传入 `-JdkHome "D:\Program Files\jdk"`、`-Maven "D:\tools\mvn.cmd"`、`-Version v1.2.3`。默认输出到新的 `build/jdbc-output/release-<时间>-<编号>/`，包括可直接运行的 `opscopilot-windows-jdbc/`、完整 ZIP 和 SHA-256 文件。也可通过 `-OutputDirectory` 指定一个不存在的新目录。每次构建独立产物，保留此前打包结果。解压整个 ZIP 后运行 `opscopilot.exe`；仅复制 EXE 不包含 JDBC 运行组件。

应用自动更新选择基础应用包，不把独立运行组件包当成应用更新。JDBC 组件独立替换；更换前需断开 JDBC 连接并退出程序。协议握手不兼容时明确提示更新组件，不尝试发送查询。

连接可以按独立于连接标记的分组组织。多个连接能够同时展开并保持各自会话；选中左侧节点不改变右侧已有查询的连接。查询和表标签跨连接显示，通过连接、数据库、表的组合区分同名对象。连接断开后保留草稿和结果，重连后可以继续使用。

连接后默认展开业务数据库，系统库默认隐藏，可在对象树选项中显示。单击表选中，双击或按 Enter 打开数据，每页 100 行；字段、索引和建表语句在对象标签中查看。表左侧箭头可展开字段。对象树搜索筛选连接与已加载的对象，不会自动连接离线数据库或遍历全部元数据；数据库右键菜单可限制筛选范围。定位按钮将当前标签对应对象定位回树中。

右键连接可连接、断开、重连、新建查询、刷新对象、编辑、复制配置、移动分组或删除连接配置。复制配置不复制密码，需要重新填写。表和视图提供数据与结构查看、复制引用、插入查询和 SQL 模板；字段提供名称复制与插入。生成 SQL 由数据库适配器负责，不自动执行；UPDATE 和 DELETE 模板以 `WHERE 1 = 0` 作为待替换的条件。跨连接插入引用时打开对应连接的新查询，避免改变原查询的执行目标。右键菜单也可以通过 Shift+F10 打开，使用方向键选择。

“执行 SQL”（Ctrl+Enter）执行选中内容；没有选区时只执行光标所在语句。“执行脚本”（Ctrl+Shift+Enter）忽略选区，执行整个编辑器中的脚本。后端根据连接方言统一识别语句边界，光标位置支持中文和 emoji。脚本或选区一次最多 32 条 SQL、总文本最多 1 MiB；语法块未闭合时先报错，不执行脚本的前半段。

MySQL 支持常见存储过程的 BEGIN/END、IF、CASE、WHILE、REPEAT、LOOP 和独占一行的 DELIMITER。通用 JDBC 识别常见匿名 DECLARE/BEGIN/END、过程定义和 IF/LOOP/CASE，以及独占一行的 `/`、替代引号和美元引号；客户端分隔符不发送给驱动。包、类型定义及声明区嵌套子程序明确拒绝，其他客户端指令没有解释器。语句边界识别不代替数据库语法校验，也不构成 Gauss 100 实机兼容性验收。

查询页签右键菜单支持重命名、复制查询、关闭当前、关闭其他、关闭右侧和关闭全部；Shift+F10 可用键盘打开菜单。操作针对右键点中的页签，批量关闭保留正在执行的页签。复制查询只复制连接、数据库和 SQL，不复制结果或发起执行；表页签保留对象名称，不提供查询重命名和复制。

查询结果支持多个语句的结果切换、复制单元格、查看完整值和导出当前结果为 CSV。导出范围仅限当前结果。结果表格只渲染可见行；长整数和小数按文本传递，保留 NULL 与空字符串的区别。

新连接默认不启用程序只读限制，实际读写权限由数据库账号决定。MySQL JDBC 支持手动开启只读限制：拒绝非查询语句，并在服务端只读事务中执行查询。通用 JDBC 不支持开启；已有配置若启用了只读限制，需在“更多设置”中明确关闭后才能提交。修改只读配置后需重新连接才能影响当前会话。写入通过 SQL 编辑器完成，当前不支持直接编辑表格单元格。

同一个连接下的查询标签共用数据库会话。允许写入时可以通过 SQL 显式控制事务；普通语句遵循服务器会话的自动提交设置。批量 SQL 按顺序执行，首个错误后停止，保留已经完成的结果；先前已提交的修改不会自动回滚。停止操作尝试向服务端发送 KILL QUERY，然后关闭查询连接；若控制连接不可用则关闭客户端连接。停止、超时和断线不能证明写入未发生，需重连后核实结果。

关闭数据库工作区释放其中的连接。切换主标签保留查询草稿与结果；刷新程序页面或关闭工作区不保存查询草稿与结果。

## 实现边界

- `pkg/dbworkspace` 管理连接配置、驱动适配、数据库会话、对象读取和有界查询。`Connector` 隔离协议和元数据方言；`QueryCanceller` 提供可选的服务端取消能力。
- `frontend-shell/src/ui/database` 提供宿主无关的 React 工作区，复用 CodeMirror SQL 编辑器、TanStack Table 和 Virtual。编辑器按需加载。
- `useDatabaseWorkspace` 管理连接、元数据访问和查询标签；`DatabaseExplorer` 管理选择、分组和菜单；`DatabaseConnectionTree` 渲染对象层级。连接选择、树展开与活动编辑标签分别维护。连接建立按配置去重，元数据读取按会话串行，其他连接可独立工作；工作区卸载后完成的连接会立即释放。
- 桌面宿主通过 Wails 自动生成绑定调用服务。共享工作区已预留 `DatabaseRuntime`，本实现尚未接入 Teams sidecar。
- FlexLayout 的工作区标签有独立的渲染、激活与关闭分派。终端上下文菜单与快捷命令仅对终端生效。
- 数据表浏览的 SQL 在后端适配器生成；前端只提交数据库、表名、页码和上限。SQL 编辑器提交文本、执行方式和 UTF-16 光标位置，后端统一选择当前语句或拆分脚本；单个语法块整体提交给驱动，不在内部的分号处分割。
- 查询返回上限可选 100、1000 或 5000 行，超时 10–120 秒。全部结果共用 8 MiB 返回内存预算（计入单元格开销），单个单元格最多 1 MiB，驱动报文上限 16 MiB。最多 16 个数据库会话，每个会话串行执行操作。
- 表数据按数据库返回顺序分页，未指定排序；并发修改可能使不同页的数据变化。CSV 仅导出当前已获取的结果，不自动扫描整张表。
- MySQL JDBC 的 TLS 模式支持关闭或启用并通过私有 Java 信任库验证证书；尚未提供自定义 CA 与客户端证书配置。

## 存储

`database-connections.json` 保存连接元数据、版本和凭据引用，使用文件锁、版本冲突检测与原子替换。密码保存在系统 Keyring 的 `OpsCopilot-Database` 服务下，不返回前端。编辑时密码留空保持原值，输入新密码可替换；密码字段旁的“使用空密码”明确提交空密码，并在保存后移除本机保存的凭据。提交前可撤销此选择。查询结果与 SQL 草稿不写入连接文件。

## 本地验证

在 Windows 上执行 `./e2e/harness/database-local.ps1` 启动独立 MySQL 8.4.8，首次使用会下载官方便携包。实例只监听 `127.0.0.1:33306`，数据、随机测试凭据和日志位于忽略的 `e2e/.runtime/database-workspace`。测试账号仅授权 `opscopilot_review` 测试库，含节点、故障、任务记录与可写临时表。

准备包含运行组件的本地产品，将 `OPSCOPILOT_TEST_JDBC_JAR` 指向本机官方 Connector/J JAR；启动 34115 上的产品后执行 `node e2e/harness/database-review.mjs`。该脚本通过真实 Wails 绑定和浏览器验证连接、对象浏览、分页、SQL、只读限制、精度、导出、取消、重连和主题布局，截图及断言写入本地 evidence 目录。测试账户及连接保存到当前本地产品实例，已有业务表不参与测试。

设置 `OPSCOPILOT_TEST_MYSQL_PORT` 和 `OPSCOPILOT_TEST_MYSQL_PASSWORD` 后，`go test ./pkg/dbworkspace -v` 会执行真实 MySQL 集成测试；未提供时仅跳过该集成用例。集成测试创建并删除自己唯一命名的数据库，不修改测试库以外的已有表。MySQL 5.7 使用兼容的驱动和元数据查询，但本地实际运行验证使用 8.4.8；历史远端验证不替代当前版本的回归验收。

额外设置 `OPSCOPILOT_TEST_JDBC_RUNTIME` 为组件目录、`OPSCOPILOT_TEST_JDBC_JAR` 为官方 MySQL Connector/J JAR 路径，即可运行真实导入和 JDBC 集成测试。覆盖驱动类错误、篡改检测、引用删除限制、连接测试、精确数值、NULL、元数据、DDL、模板、分页、只读事务、模拟 SSH 通道、取消及进程回收。测试不会下载或自动执行任意外部驱动；驱动需由调用者明确提供。

`node e2e/harness/database-explorer.mjs` 验证两个本地连接的独立展开、查询目标、同名表、分组保存和右键操作，保留体验连接供人工查看。`node e2e/harness/database-selection.mjs` 验证 SQL 编辑器在浅深色主题下的选区与当前行样式。
