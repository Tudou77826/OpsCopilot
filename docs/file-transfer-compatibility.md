# 文件传输兼容通道

正常 SFTP／SCP 仍使用流式传输，没有新增文件大小限制。本文描述 SFTP／SCP 不可用时，通过既有 SSH Shell 或提权会话完成的 Base64 兼容传输。桌面文件页签与 Agent 文件工具复用相同实现。

## 大小与传输方式

- 单文件上限为 100 MiB（104,857,600 字节），包括目录传输中的每个文件；超限时在开始传输数据前拒绝。
- 原始数据每块最多 768 KiB，100 MiB 文件需要 134 条上传数据命令、134 条下载数据命令，另有少量准备、校验及提交命令。每个上传块包含就绪和完成握手，命令数量不等于网络往返次数。
- 上传握手后通过 stdin 流式发送编码数据，由远端 `head` 定长读取、`base64` 解码，避免交互式 Shell 逐行解析文件内容。解码失败也会排空本块输入，防止残余编码数据污染后续命令。下载使用 `dd` 逐块读取，再进行 Base64 编码。
- 文件传输专用通道使用 `stty` 关闭回显、行缓冲及输出转换，不改动用户终端。远端不允许调整终端模式时，自动回退为有界 here-document，行宽为 1024 字节；这一回退路径可能显著较慢。
- 客户端不会一次性读取或解码整个文件。每条命令的响应限制为 3 MiB，包含终端回显；每条命令执行超时为两分钟，并接受取消信号。
- 继续复用已有 SSH／提权身份，不在远端安装服务或依赖 Python。兼容通道使用常见 Linux 命令：Shell、`base64`、`head`、`cat`、`dd`、`md5sum`、`stat`、`mv` 等。上传目标为符号链接时，还需 `readlink -f`。

## 校验、提交与失败处理

上传在目标所在目录创建随机名称的临时文件，逐块写入后比较本地发送数据与远端临时文件的 MD5；校验通过才替换目标。已有普通文件保留 UID、GID 和基本权限位，现有符号链接保留，上传作用于其解析后的文件。新文件默认权限为 0644。

下载在本地目标目录创建临时文件。远端传输前后的校验和、接收数据校验和及最终大小都一致后，关闭并同步临时文件，再替换本地目标。下载进度持续更新，校验阶段有独立提示。

取消、数据不完整或校验失败时，不提交临时文件。清理使用独立且有时限的上下文；服务器断线导致无法清理时，错误中明确显示可能残留的临时文件路径。最终提交命令已经发送后发生连接中断，提交结果可能未知，需要核对目标文件；不能仅凭取消按钮判断服务端是否已完成提交。

临时文件需要目标目录可创建文件，并预留新文件空间。当前不承诺完整复制 ACL、扩展属性或 SELinux 上下文，也不提供断点续传或整个目录的事务式回滚。校验用于发现传输损坏及源文件变化，不用于对抗恶意服务器。

## 模拟验证

2026-10-26 在 WSL2 Linux 中使用真实 POSIX Shell、loopback SSH 和实际 Linux PTY 进行验证；没有连接业务服务器。Windows 运行普通单元测试、相关主程序与 sidecar 回归。

| 场景 | 结果 |
| --- | --- |
| 100 MiB 文件双向传输 | 字节一致，各 134 条数据命令 |
| 真实 Linux PTY，每数据命令人为增加 5 ms 等待 | 上传约 12.52 秒，下载约 25.56 秒；这是本地模拟结果，不代表内网速度 |
| 100 MiB 测试中的 Go 堆抽样 | 最大约 5.7 MiB，仅为回调时点的进程堆观测值，不等于完整 RSS 或严格峰值 |
| 空文件、块边界、超过旧 10 MiB 限制 | 通过 |
| 超过 100 MiB | 开始远端数据操作前拒绝 |
| Shell 回显和实际 Linux PTY | 多块上传、下载通过 |
| 上传／下载中途取消、模拟断线、校验失败 | 原目标内容保留，临时文件清理 |
| 创建成功但回执丢失 | 尝试清理已创建的临时文件；清理也断线时明确报告残留路径 |
| 提交失败或本地目标并发变化 | 不把未验证内容写入目标，不覆盖并发创建的目录 |
| 符号链接、原有基本权限 | 保留链接和基本权限，数据正确 |
| 排队取消、命令静默和会话重建 | 有界取消；后续命令可重新建立会话 |
| Windows 本地替换 | 正常文件及空文件替换通过；取消、解码失败和只读目标失败时保留原文件并清理临时文件 |
| 远端解码写入磁盘满 | 模拟 `/dev/full`，校验输入排空及后续命令恢复 |
| 文件面板与常规回归 | 37 项面板测试、TypeScript 检查、Go 常规全量测试及文件传输相关 `go vet` 通过 |

测试源码为 `pkg/filetransfer/base64_transfer_test.go`，最终真实 PTY 输出保存在 `e2e/.runtime/base64-stream-pty.log`。本地模拟不等同于企业跳板机、真实 `su`／PAM 认证或所有远端 Shell 的兼容性验收；实际内网仍需复测。
