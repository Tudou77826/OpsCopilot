# 伙伴养成、功能奖章与排名

状态：首版完整产品链路已实现，包含伙伴领养、命名和换色、业务成长、正式像素动画与奖章、分类排名和成员资料。桌面与 Teams 复用同一伙伴页及素材包，通过各自适配器连接真实后台。养成采集默认关闭，在“设置 → 高级选项”启用并保存后显示个人伙伴。桌面侧边栏底部的宠物入口承接 AI 问答，紧邻快捷命令；通过助手内“养成与奖章”或设置进入伙伴页。数据结构与运维方式见 [数据存储与同步](companion-data-storage.md)。

## 助手入口与 AI 接入

桌面侧边栏底部的“伙伴助手”位于快捷命令上方，替代独立 AI 问答按钮。打开后直接使用原有知识问答、检索过程和文档引用；切换侧栏或关闭助手保留当前对话和输入草稿。助手上方默认展开伙伴展示区，以大幅像素场景呈现伙伴，名称、等级与升级经验条在同一行显示；场景高度随窗口保持在 260–340px，奖章直接挂在背景右侧并纵向排列，查看完整奖章与收起展示均使用图标按钮。陈列最多三枚已获得奖章，优先遵循已有精选顺序；尚未设置精选时按等级预览三枚，不写入展示选择。撤回后不再满足门槛的精选奖章不显示，也不自动补位。奖章名称、等级与累计数量在悬停或键盘聚焦时显示；八类统计、未解锁目标及管理操作放在完整伙伴页。可收起为名称与小头像，为问答留出空间；收起后停止读取奖章，展开时刷新本地进度。助手内“查看全部奖章”图标进入完整伙伴页，问答空白区不显示介绍文案。未启用养成时，助手仍然可用，“开启养成”打开高级选项；保存成功后才读取个人存档。

`AssistantRuntime` 定义问答与状态订阅接口，Wails 适配器调用 `AskCompanionAI` 和 `agent:status`。伙伴状态由 `CompanionHost` 读取，两者互不依赖。未来 ACP 可以通过独立适配器实现助手接口；当前未接入 ACP，也不把模型调用计入成长经验。Teams 当前没有桌面知识问答能力，其同位置宠物入口打开已有的伙伴与奖章页面。

## 1. 首版体验

每人首次免费开蛋，等概率获得七种原创像素伙伴之一，可自行命名。重开消耗50点成长经验，等概率获得当前之外的六种伙伴之一；旧伙伴不在升级时自动重抽。正常使用 OpsCopilot 获得经验，伙伴等级为 Lv.1–Lv.100；不区分幼年、成长、成熟，升级不改变形象或体型。功能奖章展示用户在内容制作、功能实践和持续使用方面的特点。

社交首版只提供分类排名和成员资料查看。用户选择参与后，同一组织中的成员可以看到其伙伴、选出的三枚奖章和八项累计统计。榜单按具体类别分别比较数量，点击成员进入个人资料。个人养成和奖章统计不依赖参加排名，也不要求先领养伙伴。

当前范围不包含好友关系、拜访、鼓励、点赞、评论、私信、赠礼和共同旅程，对应准备代码与接口已移除。美术包含七种伙伴、1–100级的抽象成长、七种基础与环境动作、完整行走衔接、兼容旧存档配色、浅深两套简洁资料背景和八种奖章中心图案。点击伙伴的招呼与开心回应是本地动作，不增加经验，也不产生网络互动。

| 伙伴 | 类型 | 默认性格 |
| --- | --- | --- |
| 微光 | 光之精灵 | 温柔、共情 |
| 赤尾 | 探险狐狸 | 果敢、行动派 |
| 苔团 | 森林树灵 | 耐心、稳健 |
| 小栓 | 复古机器人 | 严谨、高效 |
| 星角 | 星夜幼龙 | 好奇、善于联想 |
| 浪豆 | 海风企鹅 | 开朗、务实 |
| 知羽 | 学者猫头鹰 | 沉静、善于分析 |

在伙伴页开蛋获取；不提供自选物种与配色。已有伙伴保留，升级不会自动重抽。待机使用长停留和短眨眼帧，点击在招呼与开心之间切换，结束后回到待机；设置页可切换休息动作。所有动作预加载完整帧，隐藏页面与减少动态效果会暂停播放。目录与默认性格统一定义于 `pkg/companion/species.json`，桌面、Teams 与排名共享物种标识和素材。

## 2. 奖章选择与计数

选择标准是能体现具体功能、具有明确业务结果、可对同一对象去重。奖章说明操作事实，不用数量推断工作质量、故障解决效果或远端执行成功。不同类别允许来自同一工作流程，例如一份完成的案例也可以形成一篇归档；每类内部独立去重，不合成为工作总分。

下表为已接入的规则版本 1。门槛仍需依据组织试用分布评估；规则变更必须提升版本并重算。

| 类别 / 标识 | 统计口径 | 铜 / 银 / 金 | 实现依据与边界 |
| --- | --- | --- | --- |
| 知识沉淀者 `knowledge-archive` | 本人成功保存、含有效结论的独立归档场景记录；同一案例重归档仍计一篇 | 1 / 10 / 50 篇 | `ArchiveSession`、sidecar `DiagnoseService.Archive` 在成功写入后确认；用案例 ID 去重，只认启用期间登记的成果 |
| 脚本工匠 `script-created` | 本人制作并保存的非空脚本，至少一个有效启用步骤；保留稳定脚本 ID | 1 / 10 / 30 个 | `script.Manager` 有 ID 和保存结果；空脚本暂不计；启用期间新建的 ID 登记作者，随后保存有效内容才计数，导入与既有脚本的编辑不追认制作 |
| 指令工匠 `quick-command-created` | 本人制作并保存的非空快捷指令，按稳定指令 ID 计数 | 1 / 10 / 30 条 | `config.Manager.MutateQuickCommands` 可确认保存；只登记常规创建入口；内置、批量导入与既有指令的编辑不追认制作 |
| 排查记录者 `case-completed` | 已保存根因与结论的独立结案记录，按案例 ID 计一次 | 1 / 10 / 50 次 | `StopSession`、`troubleshoot.Manager.StopCase` 有保存结果；不能以 AI 回答完成替代结案，也不称“已解决故障” |
| 知识探索者 `knowledge-read` | 成功取得正文的不同知识文件，全文与场景视图按同一库内相对路径统一去重 | 5 / 20 / 100 篇 | `GetKnowledgeFileContent`、`GetKnowledgeScenarioContent` 有读取结果；读取结果后确认；刷新和搜索点击不增加数量。当前按库内路径识别，外部重命名会视为新文件，尚未实现发布文档 ID |
| 自动化实践者 `script-used` | 成功完成全部命令派发的不同脚本，按脚本 ID 计一次 | 3 / 10 / 30 个 | 桌面与 sidecar 有回放结果；取消、派发失败不计，重复回放不增加数量；展示“已应用 X 个脚本（完成派发）” |
| 快捷指令实践者 `quick-command-used` | 成功向有效会话派发的不同快捷指令，按指令 ID 计一次 | 3 / 10 / 30 条 | 后端根据已保存的指令 ID 取得正文并确认传输接受；一次广播至少一个目标成功即计一条，部分失败另行提示，不自动重试 |
| 持续实践者 `active-day` | 至少发生一项有效业务操作的累计 UTC 日期，同一天跨端只计一次 | 7 / 30 / 90 天 | 现有运营活跃标记不能直接作为账号奖章；以业务结果记录的 UTC 日期去重，崩溃补记保留原操作日期；启动应用和空挂不计 |

内容制作三类统计个人成果，不能仅凭本地保存称为团队贡献。共享知识库确认发布后才可展示“共享贡献”标识；现有归档先本地写入，再异步上传 PatchStore，本地成功和待上传队列均不等于共享成功。现有脚本和快捷指令没有团队发布能力，首版使用制作口径。对外不显示成果标题、正文、命令、服务名称、地址或本地路径。

进一步评估的方向：

| 后续奖章 | 纳入条件 | 当前缺口 |
| --- | --- | --- |
| 知识维护者 | 错误、过期内容或改进建议经维护者采纳，关联实际修订，每个问题计一次 | 当前支持评分、Issue 与 `resolved` 状态，但没有可信采纳、修订关联和维护者权限确认 |
| 知识传播者 / 自动化助力者 | 成果被其他已认证成员实际采用，同一使用者和成果去重，排除自用 | 缺少采用事实、成果作者与使用者身份；阅读、下载和派发次数不能证明解决效果 |
| 产品共建者 | 有效产品反馈被采纳并关联改进项 | 服务中心已有反馈提交与回复，但缺少账号归属、采纳语义及改进关联 |

连接次数、机器数量、传输次数或字节数、命令条数、在线时长、AI 调用量、模型消耗、升级次数、配置与凭据共享数量不作为首版奖章。这些指标容易由岗位、重试、环境或简单操作决定，不能稳定体现用户特点。后续奖章暂不进入运行时目录，也不展示占位奖章。

## 3. 查看与排名

首版提供八个分类榜，默认知识沉淀榜，可切换脚本、指令、排查、查阅、应用与活跃榜。只比较同一类别的累计数量，不混合单位。数量相同显示并列名次 `1、2、2、4`，成员 ID 仅用于稳定展示顺序，不打破并列。零数量不入榜；奖章是否已达到铜章门槛不影响有效数量入榜。

列表显示名次、显示名、伙伴缩略图、该类数量和用户选出的奖章。个人资料显示伙伴、三枚精选奖章及八项统计，未达到门槛的项显示数量和下一目标。首版仅累计榜，不提供依赖历史快照的周榜或月榜。

参加排名需明确选择，同时说明该组织成员可查看八项累计统计。退出后，服务拒绝其公开资料查询并从新的排名快照移除，个人存档和统计保留。精选奖章的取消展示仅移除卡片奖章，不等于隐藏已公开的分类统计；需要隐藏统计时退出参与。未参加的用户仍可查看自己。

应用服务从认证会话确定组织范围，不能接受客户端任意扩大查询范围。跨组织资料查询拒绝访问。排名分页使用服务端生成的快照 ID，后续页沿用同一快照，名次在分页前计算。成员退出或组织成员权限变化时相关旧快照失效，继续查询须重新获取，避免旧快照继续公开已撤回资料。

公开资料查询必须即时检查参与状态与组织权限；显示名不是身份依据。前端不能提交排名分数、奖章等级或业务确认记录；后端采集经认证同步。服务校验成员、来源、类别、对象版本并计算数量，尚不能独立证明客户端原始业务事实，不用于防作弊竞赛或绩效评估。服务返回规则版本、快照 ID、类别和数量，前端只负责展示。

## 4. 模块与数据边界

| 模块 | 所有权 | 不承担的职责 |
| --- | --- | --- |
| `pkg/companion` | 单伙伴、领养、成长规则、本地存档和事件去重 | 身份认证、排名、网络与素材解释 |
| `pkg/companionsocial` | 奖章目录、业务确认投影、展示选择、分类排序与分页 | 认证、业务成果真实性验证、数据库、HTTP 和互动功能 |
| 桌面绑定与 `internal/shellsidecar` | 已确认业务结果到个人成长的接入 | 前端申报经验与排名数量 |
| `frontend-shell/src/companion` | 共享个人/排名端口、内容契约和离散帧选择 | 权威写入成长与奖章数据 |
| `tools/pixel` 与素材门禁 | 标准化候选输出和规格检查 | 自动判断美术质量与发布未经审核的资源 |
| `pkg/achievements` 与服务中心社交模块 | 身份、组织、参与选择、确认账本、幂等同步、资料、排名快照 | 访问终端、命令、服务器和正文 |

依赖方向：业务接入依赖成长核心；排名领域使用公开伙伴 `Card`；前端通过端口访问个人与排名能力。领域包不反向依赖宿主、运营统计或存储。服务中心社交模块由管理员创建组织成员并发放独立凭据。安装 ID、Teams 插件调用者 ID、Git 作者、本机用户名、脚本远端登录 `User` 均不作为社交账号。

奖章确认记录私有字段为类别、稳定计数对象 ID、账号、单调递增版本和有效状态。领域函数 `ProjectAchievements` 按对象去重、选择最新版本并计算奖章；同版本状态冲突报错。制作成果撤回、删除或被认定无效时写入较新无效版本，数量与等级重算；撤回标记保留，不删除对象；迟到通知不能恢复旧成果。应用服务必须验证作者/来源、读取结果、结案资格或派发结果，领域函数不替代这些验证。

对象类别不同可以复用 ID；同类同一对象只计一次。活跃对象为服务认可的 UTC 日期。归档、脚本、指令和案例沿用业务对象 ID，桌面与 sidecar 共用数据目录及来源 ID；本地散列后同步。知识阅读目前使用库内路径，正式发布文档 ID 接入后需要显式迁移别名，不能直接换算法重新计数。业务成果保存与待同步确认需原子提交或有持久化补偿，再以对象和版本幂等消费。跨设备作者归属和个人使用信号属于不同可信度；首版排名是功能使用展示，不证明真实工作绩效。

现有服务中心统计按随机安装 ID 和日期汇总，部分计数来自前端，也缺少对象 ID、作者与去重证据。奖章采集使用独立的账号与选择，不能复用既有运营上报同意或把历史统计自动归属到当前账号。关闭个人养成时不采集新本地活动；退出排名时停止公开同步与查询。缺少可信归属的历史资料不自动补发奖章。

`Showcase` 接受最多三个不同类别，按用户顺序生成公开奖章，只含类别、等级和数量。未获奖类别可保留选择，撤回后未达到门槛的章不显示。`RankAchievements` 对服务提供的同组织、同快照成员统计排序，过滤未参加和零数量；它不自行验证组织权限、账户或快照存储。

共享排名端口仅提供奖章目录、个人进度、分类榜、公开资料、自身展示选择与参与开关。伙伴在资料中可为空，未领养也可查看统计。共享奖章页通过 Wails 与 Teams 业务适配器调用真实后台能力，未绑定账号时只显示本地进度和连接表单；榜单及资料来自服务端，不提供产品内演示账号或假排名。

设置页采用紧凑布局：伙伴概览整合名称、等级、升级经验条、改名与重开蛋操作；八类奖章在宽窗口排列为两行，直接显示数量与等级，计数规则和下一目标按需展开；账号状态、同步操作与分类排名合并在同一区域。成长说明和凭据重连默认收起，参与公开范围与未确认的退出状态保持可见。排名中的精选奖章使用图标与名称提示，点击成员打开完整资料。该布局由桌面和 Teams 共用，侧栏助手的大幅伙伴展示独立保留。

设置的“伙伴与奖章”页内提供“伙伴人设”折叠入口，默认只占一行，展开后编辑，内置七种性格模板。养成关闭时仍可编辑人设；发生改动后显示保存按钮，折叠编辑区不会丢弃草稿。人设用于身份、称呼和表达风格，编辑与恢复默认均需保存；未保存关闭沿用设置页确认机制。共享编辑器通过独立助手设置端口调用桌面绑定或 Teams RPC，存储见 `assistant.json`。自定义人设优先；未设置自定义文本时使用当前已启用伙伴的默认性格，切换形象不覆盖自定义文本。桌面助手使用 `AskCompanionAI`，将人设与知识问答功能规则组合；故障诊断不注入这份人设，问答也不使用诊断 JSON 和空步骤约束。人设不改变工具权限，多轮模型上下文仍未接入。

## 5. 本地成长与存储

存档为数据根下的 `companion.json`，结构和规则版本均为 1。每个存档一个伙伴，由后端验证七种物种、配色与名称。配色标识 `mint` 代表角色原色，`amber`、`lavender` 为换色。角色使用微光v8和其他六套v7正式素材包，背景使用浅深两套 `scenes/v2`，奖章使用 `medals/v2`。改名和开蛋使用存档版本检查。重开蛋在OS文件锁内验证版本与50点余额，抽取并一次原子保存扣费和新形象；陈旧请求、余额不足、抽取或保存失败不扣费。保留伙伴ID、初次相遇时间、名字、业务去重和每日上限记录，成长等级由剩余经验重算。奖章账本独立，不因开蛋扣减。

| 已确认结果 | 单次经验 | 每类每日上限 |
| --- | ---: | ---: |
| 会话连接建立 | 2 | 2 |
| 文件传输完成 | 3 | 2 |
| 脚本回放全部派发完成 | 4 | 2 |

每日总经验上限 12，使用 UTC 日期。等级由后端从剩余成长经验派生：每10点升一级，从Lv.1开始，990点达到Lv.100。快照返回等级、本级经验和升级所需经验；满级时显示满进度，后续成长经验仍可积累。等级不另存为第二套可变计数，不影响奖章数量，也不驱动素材缩放。知识等其他事件待有可靠接入后再扩展成长来源。

前端不能传入经验。结果键以事件类型加键值的 SHA-256 摘要去重；超过上限的事件也标记处理，翌日重复通知不补发。事件摘要暂不淘汰，试用需观察存档增长后制定压缩策略。未领养不积累或补发经验；关闭不读写存档、不结算、不轮询；损坏或未知版本显式报错，不重置文件。

桌面和 sidecar 使用同一数据根时，写操作执行锁内回读、校验、修改、原子写回，成功前不发布结果。配置保存成功才应用运行时开关；其他实例需重启加载。公开绑定为 `CompanionSnapshot`、`CompanionHatch`、`CompanionRename`，RPC 为 `shell.companion.snapshot/hatch/rename`，Teams 对应 `companion.snapshot/hatch/rename`。旧自选接口已移除。快照包含后端计算的等级、本级升级进度、今日经验和每日上限；前端没有写入经验的接口。

伙伴页挂载且可见时读取进度，业务经验增加后播放开心动作；领养和本地招呼播放招呼动作，休息显示睡觉动作，其他时间待机。招呼与休息只改变显示，不产生经验或网络互动。关闭页面释放轮询，角色使用 256×256 全色透明原稿素材，保留颜色层次与软边缘，不再进行低分辨率像素化。每个动作独立生成，待机与休息各八帧，招呼、开心、环顾和舒展各十二帧，普通动作12fps、步行循环十六帧12fps；待机长停留与短眨眼，招呼保持同一肢体；同动作共同基线保留开心原稿中的离地高度，不将每帧固定在地面。招呼和开心完整播放一次，结束后返回待机；静态缩略图只加载指定代表帧，离开视口暂停，仅在下一姿态边界唤醒，换色缓存最多128项。隐藏窗口暂停动效，减少动态效果设置静止显示；切换动作时保留已换色图像直至新姿态加载完成。侧边栏入口的缩略图静态显示，助手打开时显示伙伴动画。关闭养成开关后停止读取个人伙伴数据，保留默认像素图与 AI 入口。

首版账号绑定一份本地伙伴存档，同机桌面和 Teams 共用，不自动合并跨设备经验。换机需显式迁移并替换绑定；私有同步依赖绑定与 revision，旧版本不得覆盖新公开资料。当前已实现来源绑定和版本同步；公开伙伴形象及展示选择由一份来源存档管理，同机跨宿主共用。跨设备伙伴经验的合并及在线转移绑定尚未实现。

## 6. 像素内容与启用

内容包只声明形象、历史美术索引、动作、颜色配置、资源表和锚点，不声明经验或奖章门槛。奖章使用128×128全色透明金属母版，助手中48px右侧纵排，列表保持紧凑；名称、数量与进度由界面绘制。生产与验收见 [像素资源生产规范](companion-art-pipeline.md)。

旧花园货币、商店、库存、自由布局、植物内容和专用工具已删除；已有 `garden.json` 不读取、不修改、不删除，不映射为新伙伴。旧 `garden_enabled` 不迁移为启用授权，`experimental.companion_enabled` 默认 false。

当前七种伙伴正式v7包共672张全色透明帧；动作原稿、提示词和可复现配方保存在 `art/companion/roster-v5`。转出、起步、步行、停步、侧站、转入由轻量片段序列组成，姿态与位移共用开始时间；完整步幅结束在落地接触帧，点击在下一接触帧进入停步与转身。隐藏、离屏、收起及减少动态效果取消播放与移动，保留位置和朝向。生产内容包仅保存运行所需资源。桌面、共享前端与 Teams 构建均执行素材门禁。

正常走动后播放收步、转回认可待机姿态，不留在侧身站立。步行周期1333ms、原生步幅48–60px，随显示比例共同缩放；空间不足一个完整周期时不越界。环顾采用缓慢转向、两侧各停留1300ms，再回正。待机以轻呼吸和眨眼为主，45–75秒后才调度环境动作，六次中只有一次舒展、一次走动。伙伴全局显示比例为此前70%，绘制、步幅和移动范围保持一致。微光使用v8低伏兔形动作，跳步只在完整落地帧停止；其他角色沿用v7。背景随应用浅深主题切换。当前实页接入记录见 [交付验收](companion-delivery.md#微光v8接入验收)。

整体验收通过本地脚本启动真实 Wails、排名服务与隔离 SSH，在 34115 端口验证设置启用、领养、业务经验、奖章统计、两成员公开伙伴和排名、离线退出、重启恢复及关闭保留。跨日升级通过可控时钟的领域测试验证。启动和复现方式见 [完整本地实测](../e2e/SOCIAL-LOCAL.md)。本地验收、Teams 插件构建及真实组织部署分别记录，不将构建成功表述为已部署。
