# 从 Xshell 导入快捷命令（.qbl）

本文说明快捷命令导入的来源格式、字段映射、跳过与判重规则、分组落点、模块边界与验收方式。

## 1. 范围

在快捷命令面板内用一个面板完成整件事：**选定来源 → 预览（含目标分组命名）→ 执行 → 报告**。

围绕三条约束设计：

- **同机导入**。与会话导入同一前提。Xshell 的快捷按钮就在本机数据目录里，因此首选入口是自动探测，用户不需要在 Xshell 里做任何操作。
- **落点必须由用户确认**。`.qbl` 文件里没有集合的显示名，而快捷命令的分组目前不支持重命名——名字定错只能逐条命令去改。命名权因此放在写入之前。
- **有损映射要讲清楚**。`.qbl` 里只有一部分字段在 OpsCopilot 有对应能力，导入前就说明哪些会跳过、为什么。

**非目标**：`.xts` 备份包内的 `.qbl`（本机无样本可验证）、`.scs` 终端配色与 `.hls` 高亮集、sidecar 端的导入入口。

## 2. 来源格式

Xshell 的快捷按钮按"集"组织，一套按钮一个 `.qbl` 文件，存放在 `<版本>\Xshell\QuickButton Files\` 下。实测样本（Xshell 8.2，386 字节，UTF-16LE 带 BOM）：

```ini
[Info]
Version=8.2
Count=1
Expanded=1
[QuickButton]
Button_0_Name=tail
Button_0_Param=
Button_0_Icon=0
Button_0_Desc=
Button_0_Type=1
Button_0_Action=tail -f /var/log/$app/app.log
```

它是与 `.xsh` 同族的 INI 文本，编码也一致（Xshell 8 写 UTF-16LE，中文环境的老版本写 GBK），因此会话导入已有的编码回退与 INI 解析直接被复用。

解析时以 `[Info] Count` 为按钮数索引 `Button_<i>_*`；`Count` 缺失或为 0 时退化为扫描实际键名，不因为一个元数据字段缺失就一条都导不出来。

## 3. 字段映射

| `.qbl` 字段 | OpsCopilot | 说明 |
|---|---|---|
| `Button_<i>_Name` | `name` | 直接对应 |
| `Button_<i>_Action` | `content` | 原样透传，不解释其中的变量 |
| 所在 `.qbl` 文件 | `group` | 由用户在预览里确认，见第 5 节 |
| `Button_<i>_Type` | 判定能否映射 | 只放行实测确认可映射的 `1`（发送字符串）；缺失按可导入处理；其余取值不做猜测性映射 |
| `Button_<i>_Param` / `_Desc` / `_Icon` | — | 无对应字段，丢弃 |
| `[Info] Version` / `Count` / `Expanded` | — | 丢弃 |

## 4. 跳过与判重

| 情形 | 处理 | 计入报告 |
|---|---|---|
| `Type` 缺失或为 `1`，且名称、内容都非空 | 导入 | `imported` |
| `Type` 不是 `1` | 跳过并告警，告警里带原始类型值 | `skippedUnsupported` |
| 名称为空或内容为空 | 跳过并告警 | `skippedUnsupported` |
| 目标分组内已存在同名同内容 | 跳过 | `skippedExisting` |
| 同一批内重复出现 | 只保留一条 | 计入 `skippedExisting` |

判重键是「分组 + 名称 + 内容」三者全同。名称与内容都一致才算重复——同一条命令挂两个名字可能是刻意的，只比内容会误判。

「已存在」与「本批重复」合并统计：两者的下场一样（都被跳过），分开只会多一个无人看的数字。因此预览里 **可导入 + 类型不支持 + 已存在或重复 = 按钮总数**，界面上的数字可以互相校验，预览与最终报告也保持一致。

重复导入同一份 `.qbl` 是幂等的：第二次全部命中「已存在」，命令库不增长。

### 预览里的"已存在"按默认分组计算

预览按各集合的默认分组名计算重复项，改分组名后实际跳过数可能不同，以最终报告为准。这样做的原因是避免每次编辑分组名都回一次后端。

## 5. 分组落点

**一个 `.qbl` 一行，各带一个可编辑的「导入到分组」输入框，默认值 `Xshell`。**

- 两行填成同一个名字即合并为一组，填成不同名字即分开——一个机制同时表达"合并"与"分开"，只选一个集合时就只有一行。
- 输入框旁实时给出三种提示：将新建分组 / 将追加到已有分组（与面板已有分组同名）/ 将与本批其它集合合并到同一分组。前两者用面板已知的分组名判断，不需要额外请求后端。
- 默认值取 `Xshell` 而不是文件名：`.qbl` 的文件名常常是 `commands` 这类无意义的通用名，用它当分组名只会制造一个没人看得懂的分组。

`.qbl` 里没有集合的显示名（`[Info]` 只有 `Version`/`Count`/`Expanded`），会话文件里的 `[USERINTERFACE] QuickCommandSet` 也只引用集合而非定义名称，因此分组名无法从文件恢复，只能由用户确认。

## 6. 界面

入口是快捷命令卡片流里紧挨「+ 添加」的虚线「导入」块（与现有卡片同规格、带文字标签）。宿主未提供导入能力时不渲染该入口——与 sidecar 的能力降级约定一致。

面板三步：

1. **来源**：本机检测到的快捷按钮目录（单选，默认选中最新版本，显示"X 套按钮 / Y 条"）+ 手动选 `.qbl` 文件或目录。底部只有一行「将从此处导入：<路径>」作为唯一的选择结论。
2. **预览**：汇总卡片（按钮集 / 按钮总数 / 将导入 / 类型不支持 / 已存在或重复）+ 每集合一行（集合名、可导入与总数、目标分组输入框、三种落点提示）+ 一条说明"只搬名称与命令文本"+ 告警列表（含每条被跳过的原因）。
3. **报告**：已导入 / 已存在或重复 / 类型不支持 + 实际写入的分组 + 告警列表。

导入成功后后端推送一次命令列表变更，打开着的面板据此立即刷新，不依赖轮询。

## 7. 模块边界

| 层 | 位置 | 职责 |
|---|---|---|
| 解析与合并计划 | `pkg/xshellimport`（`qbl.go`、`plan_quickcmd.go`） | 纯叶子包：只依赖标准库与 `x/text`；写入通过 `CommandWriter` 端口注入，不依赖 `pkg/config`，可脱离应用独立测试 |
| 命令存储 | `pkg/config` | `ImportQuickCommands` 批量导入：一次加锁、判重、补 ID、只写盘一次，失败回滚内存；`saveQuickCommands` 改为原子写 |
| 边界门面 | `app_quickcmdimport.go` | 独立子文件，只做 Wails 边界转换与原生对话框；`app.go` 不新增领域逻辑 |
| 端口与适配器 | `frontend-shell/src/ui/ports.ts`（`QuickCommandHost` 可选方法）、`frontend/src/shell-adapter/wailsQuickCommandHost.ts` | 5 个可选方法；方法缺失时显式抛错而不是静默返回空值 |
| 面板 | `frontend-shell/src/ui/quickcmd/QuickCommandImportDialog.tsx` | 三步流程；预览与报告原语复用 `ui/common/ImportParts.tsx`（与会话导入共用） |

`pkg/sessionimport` 在本版本更名为 `pkg/xshellimport`：该包现在同时承载会话与快捷命令两类 Xshell 落盘格式的解析，原名已不准确。

### 边界契约

导入结果里的集合字段（`groups`/`rows`/`warnings`）一律返回空集合而不是 `null`。Go 的 nil slice/map 会序列化成 `null`，前端按数组处理就会抛渲染异常，而 React 的渲染异常会卸载整棵组件树。前端同时做了容错，但边界本身不产出这种形状。这条契约由 `app_quickcmdimport_test.go` 钉住。

## 8. 已知边界

- **只支持"发送字符串"类型的按钮**。脚本、菜单、带参数提示等类型在 OpsCopilot 没有对应能力，跳过并在告警里带上原始类型值，不做猜测性映射。
- **命令里的变量原样透传**。Xshell 快捷按钮里可能有 `$app` 这类变量，能否解析取决于目标服务器的 shell 环境；导入不会展开或改写命令内容。
- **分组名以用户输入为准**。`.qbl` 中不含集合显示名，文件名往往无语义，因此默认值是 `Xshell` 而非文件名。
- **导入后不自动执行**。命令只是进入命令库，需要用户点击才发送到终端。
- **`.xts` 内的 `.qbl` 不处理**，也不支持导出回 Xshell。

## 9. 验证

自动化：

- `pkg/xshellimport` 60 个用例：真实 `.qbl` 形态、`Count` 缺失时扫描键名兜底、UTF-16LE 与 GBK 两种编码、目录内忽略非 `.qbl`、`Type≠1` 与空字段的跳过原因、批内去重与前缀判重、分组指派与回落、整批只写盘一次、写失败上抛、空输入非 nil 集合、预览与执行结果一致。
- `pkg/config` 新增 6 个用例：批量补 ID 与批内去重、同名同内容跳过与三类不该跳过的反例、全是重复项时不写盘、空分组归一、写失败回滚、无临时文件残留。
- app 层新增 7 个边界用例：空目录的集合字段非 null、真实形状下数字自洽且每行带分组名与来源、分析与执行一致且真的落盘、重复导入幂等、告警含原因与原始类型、三类错误提示、未注入配置管理器时不 panic。
- 前端新增 12 个面板用例（来源默认选中、能力缺失不渲染、null 集合容错、分组名随指派带到后端、三种落点提示、宿主对象重建不重置流程、取消零调用等）与 5 个业务用例（入口、预览条数、改分组名后导入并刷新面板、取消不写入、全部重复时无新增）。

实机（`start_dev.bat`，Windows + 本机 Xshell 8.2）：

- 应用启动无报错。
- 自动探测到本机 `QuickButton Files` 目录并默认选中，界面显示"Xshell 8 · 1 套按钮 / 1 条"。
- 分析结果与真实文件内容一致（1 个集合、1 条按钮、1 条可导入、0 条跳过）。
- 执行导入后命令落盘（`quick_commands.json`，35 条、ID 唯一、无临时文件残留），面板分组条出现 `Xshell` 分组，该分组下的 `tail` 卡片标题为完整命令内容。
- 重复导入同一份 `.qbl`：预览显示可导入 0 条，报告显示「0 已导入 / 1 已存在或重复」，命令库未增长。
- 连接真实服务器后点击导入的 `tail` 卡片，命令被发送到该会话的终端并执行。
