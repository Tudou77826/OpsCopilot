# 从 Xshell 导入快捷命令（.qbl）

本文说明快捷命令导入的来源格式、字段映射、跳过与判重规则、粒度分层、模块边界与验收方式。

## 1. 范围

在快捷命令面板内用一个面板完成整件事：**选定来源 → 预览（逐条取舍与编辑）→ 执行 → 报告**。

围绕四条约束设计：

- **同机导入**。与会话导入同一前提。Xshell 的快捷按钮就在本机数据目录里，因此首选入口是自动探测，用户不需要在 Xshell 里做任何操作。
- **粒度要到单条命令**。Xshell 里的按钮名称常常很潦草、一套按钮里往往混着不同类别的命令，所以勾选、改名、改内容、指定分组都放在写入之前完成，而不是导入后再逐条收拾。
- **落点参考 OpsCopilot 现状**。只看导入的东西是不够的：同一条运维命令该进哪个分组，取决于 OpsCopilot 里已经有哪些分组、这条命令是不是已经在某个分组里。这两件事都摆在界面上，并作为默认落点。
- **落点必须由用户确认**。`.qbl` 文件里没有集合的显示名，而快捷命令的分组目前不支持重命名——名字定错只能逐条命令去改。命名权因此放在写入之前。
- **有损映射要讲清楚**。`.qbl` 里只有一部分字段在 OpsCopilot 有对应能力，导入前就把不可导入的条目列出来并说明原因。

**非目标**：`.xts` 备份包内的 `.qbl`（本机无样本可验证）、`.scs` 终端配色与 `.hls` 高亮集、sidecar 端的导入入口。

## 2. 来源格式

Xshell 的快捷按钮按"集"组织，一套按钮一个 `.qbl` 文件，存放在 `<版本>\Xshell\QuickButton Files\` 下。实测样本（Xshell 8.2，386 字节，UTF-16LE 带 BOM）：

```ini
[Info]
Version=8.2
Count=1
Expanded=1
[QuickButton]
Button_0_Name=tail
Button_0_Param=
Button_0_Icon=0
Button_0_Desc=
Button_0_Type=1
Button_0_Action=tail -f /var/log/$app/app.log
```

它是与 `.xsh` 同族的 INI 文本，编码也一致（Xshell 8 写 UTF-16LE，中文环境的老版本写 GBK），因此会话导入已有的编码回退与 INI 解析直接被复用。

解析时以 `[Info] Count` 为按钮数索引 `Button_<i>_*`；`Count` 缺失或为 0 时退化为扫描实际键名，不因为一个元数据字段缺失就一条都导不出来。

## 3. 字段映射

| `.qbl` 字段 | OpsCopilot | 说明 |
|---|---|---|
| `Button_<i>_Name` | `name` | 直接对应 |
| `Button_<i>_Action` | `content` | 原样透传，不解释其中的变量 |
| 所在 `.qbl` 文件 | `group` | 由用户在预览里确认，见第 5 节 |
| `Button_<i>_Type` | 判定能否映射 | 只放行实测确认可映射的 `1`（发送字符串）；缺失按可导入处理；其余取值不做猜测性映射 |
| `Button_<i>_Param` / `_Desc` / `_Icon` | — | 无对应字段，丢弃 |
| `[Info] Version` / `Count` / `Expanded` | — | 丢弃 |

## 4. 跳过与判重

跳过分两个阶段，用户看到的"跳过"与最终写入的结果因此可以对齐。

**预览阶段（解析与勾选之前）**：不可导入的条目仍然列出来，但置灰、加删除线并写明原因，不可勾选。

| 情形 | 处理 |
|---|---|
| `Type` 缺失或为 `1`，且名称、内容都非空 | 可勾选（默认勾选） |
| `Type` 不是 `1` | 置灰，原因带原始类型值 |
| 名称为空或内容为空 | 置灰，原因说明缺什么 |
| 按集合默认分组判断已存在同名同内容 | 标记「已存在」，仍可勾选（勾了也会被跳过） |

**执行阶段（按用户最终决定）**：只写入用户勾选并编辑后的条目。

| 情形 | 处理 | 计入报告 |
|---|---|---|
| 勾选且名称、内容非空，且目标分组内没有同名同内容 | 写入 | `imported` |
| 目标分组内已存在同名同内容 | 跳过 | `skippedExisting` |
| 同一批内重复出现 | 只保留一条 | 计入 `skippedExisting` |
| 名称为空或内容为空 | 跳过并告警 | `skippedUnsupported` |
| 回传了该集合里本就不可导入类型的同名条目 | 跳过并告警（兜底，界面上选不到） | `skippedUnsupported` |

判重键是「分组 + 名称 + 内容」三者全同。名称与内容都一致才算重复——同一条命令挂两个名字可能是刻意的，只比内容会误判。

「已存在」与「本批重复」合并统计：两者的下场一样（都被跳过），分开只会多一个无人看的数字。

重复导入同一份 `.qbl` 是幂等的：第二次全部命中「已存在」，命令库不增长。

### 预览的数字与报告的关系

预览里的三个数字——将导入 / 已存在（跳过）/ 类型不支持（跳过）——**在界面上实时算出**，其中"已存在"按每条命令最终的分组、名称、内容判定（含批内去重），与后端同规则。因此在预览里改分组、改名、改内容、取消勾选，数字都立刻跟着变，且与执行后的报告一致。

这一点不能用分析阶段算好的静态标记：是否已存在取决于目标分组，而分组正是用户要在预览里改的东西——按默认分组算死的标记会在换分组后给出相反的数字。

分析接口仍然返回一组计数（`importable` / `existing` / `unsupported` 与每段的同名三项），它们是"全部勾选 + 按默认分组"这一种假设下的快照，供非界面调用方使用；界面不使用它们，以免与实时数字并存造成两套真相。

## 5. 三层粒度

导入面板的粒度分三层，每一层都可以改：

| 层级 | 能做什么 |
|---|---|
| 集合级 | 勾选要导哪几套按钮；每套填一个默认分组 |
| 命令级 | 逐条勾选；全选 / 全不选；收起 / 展开；不可导入的类型置灰不可选 |
| 字段级 | 逐条改名称与命令内容；逐条覆盖目标分组（留空跟随集合） |

**为什么细化到这个程度**：Xshell 里的按钮名称常常很潦草、一套按钮里往往混着不同类别的命令，而导入后要逐条调整就得反复打开编辑弹窗。把决定权放在写入之前，用户只需要在一个地方对齐。

**分组名为什么由用户确认**：`.qbl` 里没有集合的显示名（`[Info]` 只有 `Version`/`Count`/`Expanded`），会话文件里的 `[USERINTERFACE] QuickCommandSet` 也只引用集合而非定义名称，因此分组名无法从文件恢复。默认值取 `Xshell` 而不是文件名——`.qbl` 的文件名常常是 `commands` 这类无意义的通用名。

**集合分组的实时提示**：将新建分组 / 将追加到已有分组（与面板已有分组同名）/ 将与本批其它集合合并到同一分组。前两者用面板已知的分组名判断，不需要额外请求后端。两套按钮填成同一个名字即合并，填成不同名字即分开。

**条目的目标分组**：留空表示跟随所属集合的分组；填了就以它为准。因此一套按钮可以拆到多个分组，也可以把多套按钮合并到同一个分组。

### 落点参考现状

只看导入的东西不够，还要看 OpsCopilot 里已经有什么：

- **现状一览**：来源页列出「共 N 条，M 个分组」以及各分组的条数。空库时明确说明"目前还没有快捷命令，导入时会新建分组"。
- **分组选择器**：集合分组与逐条分组都是选择器——列出全部现有分组、逐条额外提供「跟随集合」，需要新分组时走「＋ 新建分组…」再输入。此前是纯文本框，用户看不到已有哪些分组，只能盲打，于是同一件事容易散成「K8S 运维」和「K8s 操作」两个分组。
- **默认落点跟随现状**：某套按钮里如果有命令的内容已经存在于某个分组，默认分组就取那个分组；同一内容出现在多个分组时取命中条数最多的那个。
- **逐条标出所在位置**：一条命令若与现有命令**分组、名称、内容**都相同，标「已存在」并计入跳过；若只是**内容**相同（名称不同），标「已在某分组」，提示它其实已经有对应的命令，可取消勾选或改名称对齐。

区分这两种标记是有意的：判重规则是三者全同，所以"内容相同但名称不同"仍然会被写入——它到底算重复还是算另一个叫法的同一条命令，只有用户知道，界面负责把事实摆出来。

**为什么默认落点要参考现状**：分组目前不支持重命名。如果默认总是指向一个凭空新建的分组，用户事后要逐条命令去改才能把同一件事收拢到一处。

## 6. 界面

入口是快捷命令卡片流里紧挨「+ 添加」的虚线「导入」块（与现有卡片同规格、带文字标签）。宿主未提供导入能力时不渲染该入口——与 sidecar 的能力降级约定一致。

面板三步：

1. **来源**：本机检测到的快捷按钮目录（单选，默认选中最新版本，显示"X 套按钮 / Y 条"）+ 手动选 `.qbl` 文件或目录；底部一行「将从此处导入：<路径>」作为唯一的选择结论。另一块是「OpsCopilot 现有命令」，给出条数、分组数与各分组条数，作为落点判断的依据。
2. **预览**：三张汇总卡片（将导入 / 已存在（跳过）/ 类型不支持（跳过），按当前决定实时算出）+ 每套按钮一段（集合勾选框与条数、集合分组选择器与其落点提示、全选 / 全不选 / 收起展开、逐条命令行）+ 一条说明 + 告警列表。
   逐条命令行是「勾选框 · 名称（带"已存在"/"已在某分组"标记）· 命令内容 · 分组选择器（跟随集合 / 现有分组 / 新建）」；不可导入的条目为删除线 + 置灰 + 原因，且没有勾选框。
   「确认导入」按钮上直接带本次将写入的条数；一套都没勾选时禁用。
3. **报告**：已导入 / 已存在或重复 / 不可导入 + 实际写入的分组 + 告警列表。

导入成功后后端推送一次命令列表变更，打开着的面板据此立即刷新，不依赖轮询。

## 7. 模块边界

| 层 | 位置 | 职责 |
|---|---|---|
| 解析与合并计划 | `pkg/xshellimport`（`qbl.go`、`plan_quickcmd.go`） | 纯叶子包：只依赖标准库与 `x/text`；写入通过 `CommandWriter` 端口注入，不依赖 `pkg/config`，可脱离应用独立测试 |
| 命令存储 | `pkg/config` | `ImportQuickCommands` 批量导入：一次加锁、判重、补 ID、只写盘一次，失败回滚内存；`saveQuickCommands` 改为原子写 |
| 边界门面 | `app_quickcmdimport.go` | 独立子文件，只做 Wails 边界转换与原生对话框；`app.go` 不新增领域逻辑 |
| 端口与适配器 | `frontend-shell/src/ui/ports.ts`（`QuickCommandHost` 可选方法）、`frontend/src/shell-adapter/wailsQuickCommandHost.ts` | 5 个可选方法；方法缺失时显式抛错而不是静默返回空值 |
| 面板 | `frontend-shell/src/ui/quickcmd/QuickCommandImportDialog.tsx` | 三步流程；预览与报告原语复用 `ui/common/ImportParts.tsx`（与会话导入共用） |

`pkg/sessionimport` 在本版本更名为 `pkg/xshellimport`：该包现在同时承载会话与快捷命令两类 Xshell 落盘格式的解析，原名已不准确。

### 边界契约

1. 导入结果里的集合字段（`groups`/`rows`/`warnings`，以及每段的 `items`）一律返回空集合而不是 `null`。Go 的 nil slice/map 会序列化成 `null`，前端按数组处理就会抛渲染异常，而 React 的渲染异常会卸载整棵组件树。前端同时做了容错，但边界本身不产出这种形状。这条契约由 `app_quickcmdimport_test.go` 钉住。
2. 执行接口以回传的条目为准（名称、内容、目标分组可能都是用户在界面上改过的），不再回到 `.qbl` 重新推导；解析只用于集合级告警与兜底校验。请求里没有出现的集合、或条目列表为空的集合，都不写入任何命令——"没勾就不导"比"空请求等于全都要"安全，也更好预料。

## 8. 已知边界

- **只支持"发送字符串"类型的按钮**。脚本、菜单、带参数提示等类型在 OpsCopilot 没有对应能力，在预览里置灰不可选，并带上原始类型值。不做猜测性映射。
- **命令里的变量原样透传**。Xshell 快捷按钮里可能有 `$app` 这类变量，能否解析取决于目标服务器的 shell 环境；导入不会展开或改写命令内容（界面上改了就是改了）。
- **分组名以用户输入为准**。`.qbl` 中不含集合显示名，文件名往往无语义，因此默认值是 `Xshell` 而非文件名。
- **导入后不自动执行**。命令只是进入命令库，需要用户点击才发送到终端。
- **`.xts` 内的 `.qbl` 不处理**，也不支持导出回 Xshell。

- `pkg/config` 用例：批量补 ID 与批内去重、同名同内容跳过与三类不该跳过的反例、全是重复项时不写盘、空分组归一、写失败回滚、无临时文件残留。
- app 层 10 个导入用例：空目录的集合字段非 null、逐条明细含不可导入项且带原因、真实形状下数字自洽、逐条改名/改内容/改分组真的落盘、取消集合不写盘、分析与执行一致、重复导入幂等、三类错误提示、未注入配置管理器时不 panic。
- 前端 32 个面板用例（现状一览与空库提示、同内容命令的默认落点、分组选择器列出/选择/新建/返回、逐条"已存在"与"已在某分组"两种标记、改名/改分组后标记与数字实时重算、批内重复只算一条、逐条勾选与汇总联动、改内容与逐条分组随请求回传、取消集合不参与导入、`items` 为 null 的容错、命令库读取失败不崩、宿主对象重建不重置流程、取消零调用）与 7 个业务用例（入口、逐条预览、命令级取舍与编辑真的到后端、取消集合、落盘后报告与面板刷新、取消不写入、全部重复时无新增）。

实机（`start_dev.bat`，Windows + 本机 Xshell 8.2）：

- 应用启动无报错；自动探测到本机 `QuickButton Files` 目录并默认选中（"Xshell 8 · 1 套按钮 / 1 条"），分析结果与文件内容一致。
- 来源页正确显示现状：「共 36 条，9 个分组：开发机器 6 · 容器命令 6 · K8s 操作 6 · 常用密码 5 · 默认 5 · Nginx 维护 5 · 123 1 · 日志排查 1 · Xshell 1」。
- 集合分组与逐条分组都列出这 9 个现有分组，逐条另有「跟随集合」，都可选；需要新分组时走「＋ 新建分组…」再输入。
- 该命令此前已导入过（`tail` 在 `Xshell` 分组）：默认落点自动指向 `Xshell`（提示"将追加到已有分组"）并在行上标「已存在」，汇总为「将导入 0 / 已存在 1」——既没有凭空新建分组，也没有谎报会写入。
- 逐条改名 + 改内容 + 覆盖分组 + 集合分组同时生效：报告显示「1 已导入」，落盘为 `跟踪应用日志` / `tail -F /var/log/$app/app.log`（注意是 `-F`，证明内容确实被改过）/ 分组 `日志排查`（覆盖了集合的 `运维命令`，因此没有产生 `运维命令` 分组）。
- 把集合分组改成一个新分组后，同一屏内变为「将导入 1 / 已存在 0」、标记消失、按钮显示「确认导入 1 条」——"已存在"随目标分组实时重算。
- 取消勾选唯一一条后：段内显示"将导入 0 条"，确认按钮不再带条数，报告为「0 已导入」，命令库条数不变。
- 重复导入同一份 `.qbl` 幂等（全部命中「已存在」且不增长）。
- 连接真实服务器后点击导入的卡片，命令被发送到该会话的终端并执行。
