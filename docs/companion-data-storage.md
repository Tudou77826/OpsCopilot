# 功能奖章的数据存储与同步

状态：伙伴开蛋与成长、本地奖章采集、确认账本、离线队列、成员凭据、服务端存储、分类排名和资料查看已实现。桌面与 Teams 使用同一共享伙伴页及正式像素素材。真实组织服务部署及组织试用独立于本地交付。

## 存放位置

| 数据 | 位置 | 内容与用途 |
| --- | --- | --- |
| 业务原件 | 原知识目录、脚本目录、录制目录、`quick_commands.json` | 正文、命令与排查记录沿用业务模块；不会上传给排名服务 |
| 伙伴进度 | 数据根下 `companion.json` | 一个伙伴、名称、历史配色、剩余成长经验和成长事件去重 |
| 伙伴人设 | 数据根下 `assistant.json` | 本机自定义人设提示词；与养成开关、成员绑定和公开奖章独立 |
| 个人奖章 | 数据根下 `achievements.json` | 本地对象确认、版本、成果索引、补偿意图、账号绑定、参与选择和待同步队列 |
| 成员凭据 | 操作系统 Keyring，服务名 `OpsCopilot-Social` | 按服务地址、账号、存档来源隔离；JSON 不存凭据 |
| 社交服务数据 | 服务中心数据目录下独立 `social.db` | bbolt 数据库，与既有运营统计 `service.db` 分开 |
| 排名分页 | 服务进程内缓存 | 最多 64 个快照，每个最长两分钟；淘汰、服务重启或可见性变化后须刷新 |

桌面与本地安装模式的 sidecar 共享同一数据根、账本和来源 ID。独立 sidecar 使用自己的 `--data-dir`。关闭 `experimental.companion_enabled` 时不读取、写入或同步奖章账本；已有存档保留。关闭实验功能不等于退出组织排名，已公开资料须通过“退出排名”撤回。

人设设置仅保存 `personaPrompt`，最多 4000 字；空值使用当前已启用伙伴的默认性格，无已启用伙伴时使用通用默认人设。七种物种及性格为内置目录 `pkg/companion/species.json`，不复制进存档。读取返回默认文本与文件内容的 SHA-256 版本，保存时在 OS 文件锁内验证该版本并原子替换，陈旧编辑或损坏文件不能覆盖当前设置。物种只由开蛋决定，用户不能指定；默认人设跟随抽到的物种，自定义人设保留。桌面伙伴问答每次请求读取已保存人设；人设只随主动问答提交给已配置的模型，不进入排名资料或同步队列。

## 本地账本

结构版本为 1。每份存档拥有一次生成并持久化的 `sourceId`，未绑定时用本地随机身份计算进度。绑定管理员发放的成员账号后，对账本明确确认归属；不会读取旧业务文件批量补发。

| 字段 | 含义 |
| --- | --- |
| `receipts` | 按“类别＋对象 ID”保存最新确认，字段为 `kind/objectId/contributor/revision/active` |
| `pending` | 同一对象仅保留最新待同步状态；新增、清空、删除或恢复会合并为最终版本 |
| `references` | 已登记制作成果的私有业务 ID，用于核对删除与资格变化；不出现在绑定返回值或网络请求中 |
| `intents` | 业务写入之前保存的意图，含类别、业务 ID、目标有效状态和原 UTC 日期 |
| `binding` | 服务地址和认证成员信息；禁止把已有存档直接换绑到其他账号 |
| `participationPending` | 参与选择尚未获服务确认；明确保存 `false`，不能与“无待处理选择”混淆 |
| `profile/profilePending` | 自己选择的最多三种奖章、伙伴公开外观和来源版本，支持离线保存与重试 |
| `companionRevision` | 已投影的本地伙伴版本，阻止迟到的成长通知覆盖较新的名称、配色或等级 |

业务对象 ID 经 SHA-256 处理后同步，类别各自去重。使用确认不包含标题、正文、命令、主机或本地路径。活跃对象是 UTC 日期。知识阅读目前以知识目录和规范化路径识别文件，全文与段落共享同一对象；同名文件位于不同知识目录时分别计数。外部改名或移动知识目录尚不能识别为同一文档，正式发布文档 ID 接入时需要明确迁移别名。

每次修改先取得 OS 文件锁，在锁内重新读取并校验账本，再通过临时文件、同步落盘和原子替换写回。锁由操作系统持有，进程崩溃会释放。损坏或未知版本显式报错，不能覆盖原文件。来源 ID、补偿记录与成果索引均属于私有数据，不通过 Wails/RPC 状态接口暴露。

`companion.json` 独立保存私有经验和事件摘要；等级由后端按剩余成长经验派生，不重复持久化。每10点经验升一级，范围1–100；满级后经验继续积累，可用于重开蛋。公开卡片仅含物种、名称、配色和等级，不包含原始经验或升级进度。开蛋、改名和成长后在奖章账本中排队更新卡片，不直接发网络请求。查询奖章状态或同步时核对伙伴存档，修复伙伴已保存但投影失败的情况。相同卡片不生成新的公开版本；修改精选奖章时，在同一锁内保留最新伙伴卡片。编辑器保存进入编辑时的伙伴版本，后台冲突检查不会被轮询更新绕过。

首次开蛋免费，从七种物种中使用系统加密随机数等概率抽取；重开消耗50点经验，从当前之外的六种物种中等概率抽取，使用原色。`Hatch(revision)`在同一OS文件锁内回读、验证版本和余额、生成结果、扣费、增加修订号并原子替换文件。随机数或写入失败没有已发布的内存状态；重复提交同一修订号只允许一次成功。开蛋不会清理`seen`和`daily`，因此不能重开每日额度或重复领奖。

新伙伴沿用同一个私有伙伴槽位：ID、名字、初次相遇时间和剩余经验保留；物种与配色替换。不新增第二份等级、货币或背包数据，也不需要迁移旧存档。快照的`hatchCost/canHatch`由后端提供；首次费用为0，已有伙伴费用为50，经验不足时禁止重开。桌面绑定仅保留`CompanionSnapshot/CompanionHatch/CompanionRename`，sidecar及Teams对应`snapshot/hatch/rename`；旧自选接口不可调用。插件兼容描述升级为API revision 2，并要求`companion.hatch.v1`能力；新旧插件与可执行文件不能混用，共享配置版本仍为1。

已有伙伴存档保留原经验和修订号，读取后即计算新等级。旧公开卡片的阶段字段仅用于读取兼容，不继续展示或写入新卡片；未经刷新时显示“等级待更新”。同步恢复允许同一伙伴版本的阶段卡片一次性更新为等级卡片，要求名称、物种、配色一致，保留精选奖章，并提高公开投影版本。正常的同版本改写和迟到通知仍被拒绝，不放宽排序保护。

## 业务确认与崩溃恢复

制作或结案写入执行以下顺序：持有账本锁，落盘补偿意图，调用业务保存，成功后写入确认和待同步状态，移除意图。业务保存失败不发奖；正常失败移除该意图。业务原件采用原子写回，避免恢复时读取半份 JSON 或 Markdown。

如果业务已保存而最后一次账本写回失败，原意图保留。查询个人状态或同步前，后台通过业务 ID 读取实际原件，核对目标状态，再补记确认；首次有效结果使用意图记录的原日期。读取失败、JSON 损坏或标识不匹配时保留意图并报错，不能当作删除。状态核对只处理启用期间登记过的制作成果；导入、内置及启用前旧成果不会因编辑或扫描被追认为制作。

已登记脚本、指令和归档的删除或失去有效内容会写入较新无效版本，累计数量和奖章等级重算。恢复同一个已登记对象可重新生效。核对扫描本身不增加活跃天数。归档用案例 ID 和保存记录中的会话标记识别，同一案例再次归档只计一次；同一服务和模块的连续归档采用加锁追加，保留此前记录。

阅读、脚本派发、快捷指令派发、连接与传输的使用结果在业务成功后记录。终端操作无法与本地文件构成数据库事务；派发成功后进程立即崩溃或账本落盘失败可能漏记一次使用，但不会为了补奖自动重新发送命令。只完成点击、空脚本、取消和全部派发失败不计数。广播至少一个目标接受写入即确认一条指令，部分失败单独提示。

## 认证、同步与服务数据库

管理员创建成员并指定组织，首次返回随机成员凭据；服务端只保存其摘要。成员访问使用 Bearer 凭据，凭据停用后全部成员接口立即拒绝。安装 ID、Teams 浏览器身份、机器用户名和 SSH 登录用户均不能作为社交身份。

客户端同步按对象排序，每批最多 100 条，只发送确认结构和来源 ID。服务端检查认证账号、来源、类别、对象 ID、版本、有效状态及日期，并在一次 bbolt 事务中写入最新对象和统计投影。重复或较旧版本不改变统计；同版本状态冲突整批失败。制作成果的首次来源拥有后续修改权限；伙伴公开外观和精选奖章也由一份来源存档管理。跨设备使用记录可合并，不自动合并伙伴经验或转移制作来源。

客户端收到确认后只移除完全一致的待同步版本。服务已接收而客户端未收到响应时，队列保留，随后重试不会重复计数。请求途中产生的新版本不会被旧确认移除。桌面与 sidecar 对共享来源的网络同步也通过 OS 锁串行执行。

“退出排名”先持久化本地选择并停止后续上传，再请求服务撤回；离线失败时保存待重试选择，重新连接不会覆盖它。奖章页明确提示公开资料可能仍可见。恢复网络后点击“立即同步”，优先处理参与选择，收到服务确认才清除待处理状态；退出后保留未上传成果。展示选择的版本由后台产生，前端不能申报版本、数量或等级。

`social.db` 的桶为 `meta/members/tokens/receipts/totals`。`meta` 保存结构版本和组织可见性版本；`receipts` 按成员分桶，保存每个对象的最新有效版本及来源；`totals` 为可从对象重算的汇总。无效版本作为撤回标记保留，不因备份或清理删除。当前不保存完整事件审计历史。

排名服务验证账号和组织后，从服务端统计生成分类榜，数量相同显示并列名次，零数量不入榜。后续分页使用同一快照。退出、成员停用或精选奖章更新会使相关组织的旧快照失效；公开资料每次查询即时检查权限。跨组织查询不返回成员是否存在。页面只提供排名与查看，不包含互动接口。

这些确认由受信任的产品后台采集，但服务端不取得业务原件，无法独立证明客户端原始操作。当前功能用于组织内使用展示，不能据此建立防作弊竞赛、共享成果采纳证明或绩效评分。

## 接口与使用

| 服务接口 | 用途 |
| --- | --- |
| `POST /api/admin/social/members` | 管理员创建成员，输入 `organizationId/displayName`，返回成员及一次性显示的 `token` |
| `DELETE /api/admin/social/members/{id}` | 管理员停用成员 |
| `GET /api/v1/social/me`、`catalog` | 认证成员与奖章规则 |
| `PUT /api/v1/social/participation`、`profile` | 参与选择和自己的公开展示 |
| `POST /api/v1/social/receipts` | 后台对象确认同步 |
| `GET /api/v1/social/rankings` | `kind/offset/limit/snapshotId` 分类分页 |
| `GET /api/v1/social/profiles/{id}` | 查看同组织参与者或自己的资料 |

桌面提供 `AchievementStatus/AchievementCatalog/SocialConnect/SocialParticipation/SocialSync/SocialShowcase/SocialRankings/SocialProfile`；sidecar 对应 `shell.social.*`，Teams 对应 `social.*`。快捷指令由桌面的 `DispatchQuickCommand` 和 sidecar 的 `shell.quickcmds.dispatch` 确认派发；Teams 保留终端所属实例、已附着浏览器写入者和回放独占检查。

在“设置 → 高级选项”勾选“启用伙伴养成与功能奖章”并保存。当前宿主立即应用开关，桌面助手显示个人伙伴，并提供“养成与奖章”；设置出现“伙伴与奖章”；其他已运行实例需重新加载配置。伙伴页提供首次免费开蛋、改名和消耗50点经验重新开蛋，不提供形象与配色自选。使用管理员发放的成员凭据连接，明确确认本地记录归属，再选择是否公开八项累计统计。未参与时保留本地积累，也可查看自己的资料。公开资料展示服务最近已同步的版本，本地尚未同步的进度以伙伴页和“我的积累”为准。

备份需要同时保留业务原件、`achievements.json`、`companion.json`，凭据从安全渠道重新发放或连接。不能复制一份存档后让两份副本独立写入：来源与版本会冲突。服务端停机后可备份完整 `social.db`；在线备份须使用 bbolt 的一致性事务快照，不能直接复制正在写入的数据库文件。尚未提供在线导出和自动迁移工具。

## 验证与发布边界

自动化测试覆盖本地关闭与损坏保护、共享写入、业务失败、跨日崩溃补记、删除与恢复、重复/迟到确认、超过 100 条分批、确认丢失、离线退出与重连、成员停用、跨组织拒绝、展示版本冲突、旧快照撤回、服务重启和凭据不落入 JSON/数据库明文。前端测试覆盖进度、最多三枚展示、显式归属、离线退出提示和资料查看。

Go 包测试及 HTTP 集成使用临时目录和测试成员，不连接实际用户账号。共享前端、桌面和 Teams 的类型检查、构建与资源门禁独立执行。Windows Keyring 已用隔离凭据验证跨实例读写；本地浏览器实测进一步验证两个独立桌面的业务采集、HTTP 同步、他人伙伴和排名，以及桌面和服务重启后的离线退出与补传。Teams 集成通过真实可执行文件、业务适配器及 sidecar 验证免费开蛋、改名、余额不足与旧自选接口拒绝、版本冲突、禁止经验申报、重启恢复和关闭保护。方法及启动命令见 [完整本地实测](../e2e/SOCIAL-LOCAL.md)。Teams 外部宿主人工操作与内网部署分别验证。

交付验证记录见 [首版交付验收](companion-delivery.md)。正式素材包已通过规格门禁、原尺寸与放大图审核、实际产品页的明暗主题和运行时换色检查。跨日升级通过可控时钟验证。`go test -race` 因本机 cgo 未启用且未提供 C 编译器而未执行；跨进程 OS 文件锁和共享存档并发测试已运行。
