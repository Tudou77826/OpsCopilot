# AI 助手的 iCode 运行组件

OpsCopilot 通过独立的 iCode 进程和 ACP 会话运行助手。运行组件来自 [openJiuwen-ai/iCode](https://github.com/openJiuwen-ai/iCode)，程序名为 `icode`；Python 包名、`CHRYS_*` 环境变量和 ACP 扩展命名空间仍为 `chrys`。无需修改 iCode 源码。

## 安装与发现

安装 iCode 并确保 `icode --version` 可运行。程序按以下顺序寻找运行组件：

1. 【设置 → AI 接入 → AI 接入】中保存的程序路径。
2. `OPSCOPILOT_ICODE_EXECUTABLE` 指定的绝对路径；未设置时兼容旧变量 `OPSCOPILOT_CHRYS_EXECUTABLE`。
3. OpsCopilot 程序旁的 `icode/icode.exe`（Linux 为 `icode/icode`），随后兼容 `chrys/` 目录中的新旧程序名。
4. PATH 中的 `icode`，最后兼容 `chrys` 程序名。

显式路径不存在或不是绝对路径时直接报错，避免静默启动另一套运行组件。兼容旧程序名不代表兼容所有旧版协议。

在设置页选择 iCode 可执行文件，或清空路径使用自动查找，然后点击「检测环境」。检测使用与真实聊天相同的隔离启动流程，逐项验证程序启动、ACP 握手、接口兼容、助手配置和独立会话初始化；失败后的步骤标为未检查。结果包含实际程序路径、运行组件版本和失败阶段，支持复制。检测不保存草稿、不调用模型、不读取用户 Skills，也不连接业务服务器。修改路径后点击设置页「保存更改」，再新建 AI 对话使用。

## 协议边界

初始化要求 ACP 协议 1、HTTP MCP，以及 `agentCapabilities._meta.chrys` 声明的扩展 API 1。必须包含 `profiles/models/write`、`profiles/agents/write` 和 `settings/reload`。接口不全时在创建会话和发送问题前报出缺失项。

扩展能力声明中的方法名不带下划线；ACP stdio 传输发送 `_profiles/models/write` 等方法名。提问回调仍为 `_chrys/request_input`：自由输入进入 `answers[].values`，选项补充说明进入 `note`。审批使用标准 `session/request_permission`，只授予本次操作权限。

每段对话使用隔离配置和工作目录，不读取个人 iCode 会话。受管进程关闭更新检查、自动标题和遥测。手动审批、停止撤权、工具审计及页签占用继续由既有边界执行。

## 模型来源

内置助手仅使用本机 iCode 已配置的模型。Windows 读取 `%APPDATA%/chrys`，其他平台读取 `~/.chrys`；未手动选择时使用 `settings.yaml` 的 `model.profile.active` 或 `CHRYS_MODEL_PROFILE` 指针确定默认模型。输入框底部显示实际模型标识，可从下拉列表切换至其他 iCode 模型。没有有效默认指针时可显式选择，不自动选择另一个服务。

模型列表只返回配置 ID、名称、模型标识与 provider。选中模型时才解析其必需认证信息，包括接口形式、服务地址、请求头、请求参数与网络选项。环境引用从当前进程与 iCode 的 `.env` 解析；不复制整个 `.env`。模型快照在首条消息时固定，避免外部配置变化使下一轮意外使用另一服务。新建对话和程序重启保留所选 ID，并重新读取该模型配置；配置失效时要求用户重新选择，不改变 iCode 默认模型或静默切换服务。

助手空闲时通过标准 ACP `session/set_model` 在同一会话切换模型，保留消息历史；执行、等待回答或授权期间禁止切换。切换先写入隔离目录中的独立模型配置，成功后才更新当前选择。请求被拒绝时继续使用原模型；传输中断导致结果无法确认时停止该会话并要求新建对话，不假装切换成功或自动重放操作。此接口需要所选 iCode 支持标准的会话模型切换。

模型选择左侧的环形指示使用标准 ACP `session/update` 中的 `usage_update.used/size` 展示当前上下文窗口占用，悬停可查看比例和 token 数；它不是累计计费 token。达到 75% 和 90% 时分别显示提醒色和高占用色。没有有效上限或尚未收到用量时显示未知状态，不估算为 0%。上下文压缩后占用可以下降；切换模型、新建对话或重启后台后等待新会话用量，不恢复旧比例。读取指示不调用模型，也不获取页签控制权。

内置助手的主对话不使用 OpsCopilot「模型服务」配置；操作自审优先使用其中配置的快速模型。旧配置中的 `model_source` 不再改变主对话模型。未配置密钥不能直接推断服务支持免认证。环境检测同时显示模型配置是否已读取，但不请求模型，因此不能证明认证或网络连通。

启动时模型密钥和 MCP 令牌通过子进程环境引用注入。运行中切换模型无法更改子进程环境，所选模型的认证引用通过私有 stdio 写入隔离模型配置，该目录随会话关闭清理。模型列表、切换结果和检测结果不返回密钥、服务地址、请求头或原始模型配置，也不导入个人会话、Agent、Hooks、Skills 或授权记录。

Windows 保留真实的 `USERPROFILE`，供安装版启动器解析操作系统目录；iCode 的配置、模型和会话目录通过独立的 `APPDATA` 隔离。不能用临时目录替换 Windows 用户配置文件路径来实现应用配置隔离，否则部分启动器会在 ACP 握手之前退出。

本地项目目录仍按每轮页面上下文提供；它们不会自动成为整个对话的无限制文件访问授权。原生本机工具经 iCode 审批，SSH、数据库和文件传输经 OpsCopilot 的 MCP 工具。

## 验证

2026-10-23 对接基线：iCode 0.30.1，源码提交 `618fd32953c45b9f6e9cb1bcc38a244a6c68d3f3`。按能力声明判断可用性，不以版本号猜测接口。

普通回归：

```powershell
go test ./pkg/agenttransport/acp ./pkg/agenttransport/mcp .
```

显式指定已安装的 iCode，可运行真实运行组件与本地确定性模型的集成测试；不使用生产模型密钥：

```powershell
$env:OPSCOPILOT_CHRYS_TEST_EXE = 'C:\path\to\icode.exe'
go test ./pkg/agenttransport/acp -run '^TestLive(Chrys|ICode)' -count=1 -v
```

这些测试覆盖握手、跨轮上下文、新建对话隔离、取消后继续、MCP、选项和自由输入提问，以及原生 Python Skill 审批与热更新。模型行为是确定性测试响应，不能据此推断真实模型的排障质量。页面联调启动器支持 `--icode=<绝对路径>`，保留 `--chrys=` 兼容参数。

## 对话与操作自审

助手发言按 ACP 消息段保留，提问、用户答案、自审及中断状态按发生顺序记录时间。当前对话及所选模型 ID 原子保存到应用数据目录的 `assistant-conversation.json`；本地项目及其选择继续使用独立的 `assistant-projects.json`。完成轮次立即保存，运行中约每秒保存已观察到的可见输出。记录有大小和条数限制，旧轮次整体淘汰。保存失败会明确提示；无法保存初始记录时不开始操作。新建对话清空当前记录，但保留模型选择和项目配置。

程序重启只恢复可见消息及配置选择。新建隔离 iCode 会话后，在用户再次发送消息时提供有界的近期历史，明确标为历史资料；隐藏的原生工具上下文和推理状态不恢复。界面提示恢复范围，未结束轮次显示中断状态。队列、待答回调、授权、占用及旧连接句柄均不恢复，也不会自动重放命令。连接表单只保留操作结果，不保存密码或原始表单数据；持久化不写入模型凭据或 MCP 令牌。用户主动粘贴进消息的内容仍属于本地对话记录。

记录无法解析或检测到其他进程修改时不自动覆盖。用户明确新建对话时，无法解析的原文件先保留为 `.unreadable-*` 备份。恢复记录不会扩大操作权限，也不代表原来的远程现场仍然有效。

### 操作结果与失败说明

信息流以业务结论为主线，普通执行默认只占一行摘要，命令、SQL 与输出按需展开。执行详情包含：远程命令展示命令及终端片段，SQL 展示语句、少量结果值及返回行数／影响行数，文件传输展示路径及已确认字节数。SQL 预览限制结果集、行列数和单元格长度，凭据类列值隐藏。本机命令、文件读写及 Skill 脚本从标准 ACP 工具通知生成记录；不从模型叙述推定执行结果。输出是有界片段，终端内容可能包含输入回显和后台输出，不等同于独立标准输出。

同一轮中，连续两项及以上的正常执行默认归为一行，显示已完成数量和最近操作；运行状态原位更新。中间的页签呈现、历史授权选择和自审保留在组内的过程记录中，不计入执行数量。展开后按原顺序逐项查看；已展开的记录不会因新增操作自动收起。助手发言、业务提问、用户回答、不同轮次或异常均结束当前分组；单条执行直接展示，失败和结果未知不进入折叠组。分组只影响展示，不改变原始消息、操作权限或执行结果。当前审批卡片仍按原规则呈现。显示片段过滤常见凭据形式；原生执行审计继续只保存标识和摘要，不写入原始命令或输出。

SQL、文件传输和远程命令结果旁提供定位图标，分别打开原 SQL 记录与结果、原传输队列和终端。模型回复中的路径、链接或页签编号不能生成这些入口。

定位只呈现已有内容，不取得控制权、不连接服务器、不重新执行 SQL 或传输文件。应用重启后可见对话保留，但原工作区可能已不存在；点击时会明确提示，不能用旧消息恢复连接或授权。

失败时展示失败环节、已确认的结果及下一步，原始诊断默认折叠并支持复制。启动任务不等于完成任务；停止时尚未确认的结果保持未知。SQL 或文件传输已完成但结果审计失败时，分别保留完成事实与审计异常，提示先核对原页签或实际文件，避免重复执行。

输入框底部显示当前页上下文：终端标明“远程”和连接状态；数据库或文件传输页签标明当前页。本地项目入口标明“本地”，有其他页上下文时收为目录图标。项目与远程资源可以同时存在，项目目录不会覆盖远程任务的目标；没有明确目标时仍须询问。普通提问不设自动答复期限，用户提交或停止才结束；有期限的操作授权过期时不会自动批准，信息流保留未授权状态。

主信息流突出助手发现、提问、用户回答及异常；连续的自审记录默认折叠为「操作记录」，可展开查看原文和时间。分组只依据宿主记录类型，不能凭措辞隐藏助手发言或错误。执行进度保留在输入区上方，助手提示词要求省略常规操作播报。回退到 iCode 自审时保留可见的简短提示，完整原因在操作记录中，审批卡片继续展示自审方式。

已授权的简单只读终端命令继续由本机规则放行。规则不能确认的命令和本机权限请求优先直连 OpsCopilot「模型服务」中的 `FastModel`，使用该配置的服务地址与认证信息，单次请求、不重试、不提供工具、禁用思考模式，输出上限 16 token。DeepSeek 使用其[思考模式接口](https://api-docs.deepseek.com/guides/thinking_mode/)要求的顶层 `thinking.type=disabled`，Qwen 系列使用模板参数 `enable_thinking=false`；其他模型不附带这两类厂商参数。输入只包含本轮要求、准确目标和原始操作，要求模型只选 A（范围内非敏感只读）、B（状态修改）、C（敏感信息或披露）、D（超出范围）、E（信息不足）。只有 A 是自动继续的候选，仍须通过宿主的人工确认边界及现场校验。

快速模型正常返回 B～E、空答或无效选项时直接转人工，不再向另一个模型寻求放行。只有快速模型名称或服务地址未配置、访问报错或超过 12 秒访问期限，才回退到独立的 iCode 自审会话。空密钥允许用于免认证服务，不单凭缺少密钥判断配置不可用。用户停止或取消不会启动回退，也不会接受迟到的结果。回退开始时在信息流明确提示原因、可能较慢，并建议配置或检查快速模型；同一轮不重复刷提示，审批卡片仍保留自审方式。

回退会话使用主对话的同一个 iCode 模型快照，不加载业务 Skills、不提供 SSH、数据库、文件或本机执行工具，并拒绝权限申请；iCode 自带的内部上下文工具不会获得业务资源。回退只接受字段完整的只读、范围匹配、非敏感结论；解析失败、45 秒超时、取消或不确定结论进入人工确认。已识别的敏感读取与修改操作不能靠任何模型的自审跳过确认。自审是模型判断，不能作为对任意脚本安全性的形式证明。

自审批准仍绑定原始命令、目标、身份、现场、占用期限和单次执行；停止或接管立即使迟到结论失效。审计区分人工批准和 AI 只读自审，不保存命令明文或模型认证信息。正式构建隐藏接手实验入口；专用测试构建可显式设置 `VITE_TERMINAL_HANDOFF_LAB=1`。
