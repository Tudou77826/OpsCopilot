# 终端助手试用

状态：2026-10-21，持续对话、消息调度、终端工作台接口与文本 Skill 接入已实现。主助手统一通过 Chrys ACP 对话，同一段对话复用 Session 与模型上下文，终端能力通过受控 MCP 工具使用。聊天不要求存在 SSH 会话；初始终端候选在提交消息时确定，模型可通过明确的工作台操作改变本轮目标，权限不随目标转移。

## 使用方式

打开右侧 AI 助手即可输入问题，没有 SSH 连接也可聊天、提问和停止。发送时如有活动终端，只把它作为本轮可选的工具目标；普通聊天不检查或绑定这个资源，也不创建终端审计、初始化 Shell 或申请占用。

模型第一次调用依赖终端的工具时，宿主才核验并绑定该目标的实际连接。没有目标或连接已失效时，工具返回缺少 SSH 的提示，模型仍可继续解释，也可明确选择已有终端或申请打开已保存的 SSH 连接。人工浏览其他页签不会把旧工具调用改送到其他节点，断连和停止仍撤销其操作权限。关闭一个尚未被工具使用的候选终端，不会取消普通聊天。

缺少资源使用结构化工具结果 `status: unavailable`，并给出 `requires: ssh` 与 `ssh_required` / `ssh_unavailable` 原因码，不返回普通 MCP 执行错误。已验证的 Chrys 版本会简化错误正文；前置条件作为正常结果返回，模型才能解释缺少的资源。该结果不含终端观察或执行凭据，不触发读取授权、初始化或占用。

首次读取终端前，用户确认允许向模型提供当前屏幕；这个动作不要求普通命令行、不初始化 Shell、不占用终端。模型需要执行一段不能被人工输入干扰的操作时，才调用 `terminal_take` 申请占用；首次接手需确认当前为空闲普通命令行。拒绝授权后本轮不能重新申请这个范围。接手授权包含当前节点的常规只读排查：状态命令、普通路径的字面量 `ls`、`cat`、有限 `head` / `tail` / `grep` 自动继续；敏感路径、持续读取、复合语法、未知选项和其他操作仍需确认。授权由宿主构造，工具参数不能扩张。

`terminal_context` 不改变占用状态：未占用时是可随人工操作变化的屏幕快照，已占用时继续使用同一把锁。`terminal_take`、`terminal_release` 由模型按需要调用，前端只按后端实际 `owned` 状态显示遮罩和徽标。`terminal_execute` 要求已有占用权，不隐式接手。模型应在关键操作段结束后、解释结果或闲聊前释放，不必等整轮结束。

Chrys 的问题支持单选、多选和补充文本。提问和命令审批不自行改变模型已有的占用；模型应在不再需要保护现场时明确释放。命令审批绑定原命令、实际连接、Shell 身份与现场，批准后在原占用内执行一次，不重新加锁或自动解锁；等待期间不能跳过审批执行另一条命令。拒绝或执行异常结束当前操作段并交还。真实助手的交互卡片在助手面板显示，固定接手体验仍在终端区显示。输入框停止、终端手动接管、关闭连接及正常页面离开撤销本轮权限和占用；迟到答案不能恢复旧运行。

## 终端工作台

三个工作台工具与四个终端工具共用当前轮次的串行调用入口：

| 工具 | 输入 | 结果与边界 |
|---|---|---|
| `workspace_list` | 无 | 返回已有终端、实际活动终端、本轮工具目标和已保存 SSH 连接的名称及访问路径；不包含密码或私钥 |
| `workspace_open` | 已保存连接 ID | 确认具体连接后打开独立 SSH 终端，沿用原连接与跳板实现；不接受模型提供地址或凭据 |
| `workspace_select` | 已有终端页签 ID | 核验实际连接，选择并等待该终端呈现后，将其作为本轮工具目标 |

连接成功与页面呈现分别确认。工作台控制器只有在目标实际选中、终端已挂载且连接编号一致时才能回执成功，工具才继续返回。新终端有独立的 Shell，不继承旧终端的目录、环境或 `su` 身份。模型切换目标前撤销旧终端的读屏同意、执行授权和占用，新目标重新确认；对同一实际连接的拒绝在本轮内保留，切走再选回不能重置拒绝。切换前或切换期间已接收的旧请求不能被重定向。

停止或呈现失败会清理尚未交付的新连接；已成功呈现的终端保留，用户可继续使用。底层拨号可能持续到既有超时，但取消后的迟到结果不能发布页签或恢复权限，清理只作用于捕获的连接实例，不关闭其替代连接。未知结果不自动重试创建，模型应先查看工作台再判断。

当前以最近注册的桌面页面为呈现控制器，旧页面不能回执新页面的操作；刷新或更换控制器停止旧轮次。工作台快照使用心跳判断是否可用，这不等同于整个助手执行权限的独立心跳租约。本节的工作台工具覆盖终端页签；数据库能力使用独立领域工具，见 [AI 数据库工作区](assistant-database-trial.md)。文件页签、多窗口协同及任意 SSH 连接配置创建尚未开放。

工作台动作在应用日志记录轮次、动作阶段、页签与实际连接编号，不记录完整配置或凭据；具体终端命令继续使用既有执行审计。工作台事件日志不替代命令审计，也不是持久化任务事务日志。

## 对话生命周期

业务知识使用[Skills 与快捷命令](assistant-skills.md)。完整 Skill 包由管理面板导入，Chrys 原生 `load_skill` / `read_skill_resource` 按需读取，附带脚本由原生工具执行；更新在下一轮重载并保留对话。远程工作台仍经应用接口与原有授权。示例只放在测试目录，不作为发行包预置内容。

首次发送消息时，宿主启动独立 Chrys 进程并调用 `session/new`。同一段对话的后续消息向原 Session 发送 `session/prompt`，历史内容由 Chrys 管理，不由前端拼接。每轮都创建新的应用工具适配器、授权范围及确认记录；前一轮的屏幕只作为历史观察，不能恢复读取权限、命令批准或页签占用。

停止先取消本轮工具权限，再发送 `session/cancel`，等待 Chrys 结束本轮。正常取消保留 Session，下一条消息可以接着讨论。超过三秒未完成取消、通信中断或异常结束时，宿主关闭进程并将对话标记为不可继续；后续明确要求新建对话，不自动重建一个丢失上下文的会话，也不自动重试未知结果的命令。

“新建对话”同时关闭旧 Session 所在进程、清理其临时目录并重置后端状态，成功后才清空页面消息。执行和取消清理尚未完成时拒绝重置；失败保留原页面。模型配置发生变化时，也要求新建对话后再使用新配置，避免静默切换模型或上下文。应用正常退出关闭保留的助手进程。

本版仅保留当前应用进程内的对话，没有跨应用重启的历史恢复或对话列表。关闭侧栏不会结束对话。强制刷新页面会丢失前端历史和待发送队列，不恢复未发送的操作；后端不会因此自动清空模型上下文，可通过新建对话明确重置。

助手始终停靠右侧，标题、创建对话和关闭操作合并为一行。待发消息、编辑区与发送工具栏共用一个输入面板；停止位于运行状态旁。回车将补充消息加入队列，Shift + Enter 换行，输入法确认候选词不发送。未提交的草稿保留。输入面板底部显示下一条消息使用的终端候选；当前任务使用不同终端时，在运行状态旁补充其目标。状态提示仅根据宿主已知的启动、处理、输出和待答状态显示，不推断具体命令正在执行。上翻阅读历史后，新输出不强制滚动，可通过“回到最新”恢复跟随。审批默认展示执行位置、完整命令、宿主判断和确认原因，模型补充目的与其他详情按需展开；确认和拒绝仍作用于原请求。

## 消息队列与立即发送

运行时提交的消息显示在输入面板顶部，最多排队 20 条。默认展示两条，可展开更多消息；预览允许两行，同一目标不重复显示，跨终端消息保留目标名称。每条消息固定提交时的终端候选及实际连接编号，执行前仍由后端重新核验；用户切换页签或重连不会将旧消息悄悄改送到新连接。消息排队不申请终端占用，也不携带前一轮的授权。

正常完成后按顺序处理下一条。每条待发消息可移除或立即发送；立即发送先请求停止当前轮次，等待启动返回、权限撤销和 Chrys 取消收尾，再将该消息移至队首，在同一段对话中继续。剩余消息保留原有顺序。停止失败时不启动新轮次，不丢弃所选消息；旧审批与占用不能由新消息恢复。

手动停止、终端接管、超时、执行失败或状态读取失败后，积压消息保留但暂停。接管后的撤权状态不等于后台已就绪；界面继续等待取消收尾完成，不提前恢复空闲操作。用户可点击“继续队列”或选择一条立即发送；没有积压消息时，新输入可以直接发起新轮次。新建对话成功才清空历史和待发消息，失败保留原状态。队列由当前页面调度，后端继续负责一进程一条执行序列和权限边界，不视为跨窗口、持久化任务系统。

审批卡片分开展示宿主快速分类、执行影响、需要确认的原因、实际节点与身份，以及模型可选的操作目的。模型目的只作参考，不能作为批准或只读证据；未知命令不被误标成“已确认危险”。此版借鉴 Chrys 的分类与解释方式，没有调用其本地代码工具审批器，也不以模型建议替代敏感操作的人工批准。

一轮最多十分钟，一段连续终端占用最多两分钟。停止撤销后续输入权；远端已经提交的进程是否结束，以实际终端观察为准。

强制结束浏览器时不能保证卸载通知送达，异常断开仍由运行期限兜底；当前尚未增加独立的前端心跳租约。

## 运行依赖

模型沿用应用已有的 OpenAI 兼容配置，依次选择复杂任务模型、兼容字段、快速模型。Chrys 程序按以下顺序发现：

1. 开发环境变量 `OPSCOPILOT_CHRYS_EXECUTABLE` 指定的绝对路径。
2. 应用旁的 `chrys/chrys.exe` 或 `chrys/chrys`。
3. 系统可执行路径中的 `chrys`。

此批没有打包 Chrys 或增加依赖安装页面。已验证版本为 Chrys 0.25.1，需要 ACP 协议 1、配置管理扩展和 HTTP MCP。该版本连接免认证模型时实际出现 SDK 认证错误，应用会给出专门提示。

预览运行组件使用独立的 v0.25.1 安装快照（提交 `f51ecead54a88dae7b6fbd502e41fc8a314d4b27`），按该版本锁文件安装，关闭可编辑安装，不引用外部 Chrys 开发目录。否则开发源码更新而虚拟环境未同步时，应用可能在握手前因缺少模块退出。启动诊断只提取允许的缺失模块名称；原始 stderr、堆栈和任意第三方输出不直接显示或写入日志。

## 模块边界

```text
AIChatPanel / useAssistantQueue → useAssistantTurn
  → Wails StartAssistantTurn（消息、可选的资源候选）
  → assistantcontrol（轮次、问题、停止、迟到结果隔离）
  → agenttransport/acp（受管 Chrys 进程和会话）
  → agenttransport/mcp（通信认证、参数转换）
  → assistanttools（绑定目标、同意、显式占用与释放）
  → workspace（页签快照、连接呈现与目标切换） ↔ 前端工作台控制器
  → terminalcontrol.Access（授权、逐次批准、审计、写入前核验）
  → 既有 SSH PTY
```

`assistantcontrol` 不依赖终端、Wails 或协议实现。`assistanttools` 是应用能力适配层；`terminalcontrol` 不导入 ACP/MCP。四个终端工具的参数不能指定连接 ID、UID、权限范围或审批 ID。`terminalcontrol.Observer` 只有读取接口，绑定实际连接，记录 `screen_read` 审计；没有提示符时身份记为未知，不用屏幕读取授权构造执行权限。

主助手使用单一的受管 ACP 入口，不再回退到旧知识问答调用。其他旧排障入口尚未迁移。`acp.Conversation` 管理进程、Session 和取消收尾；`assistantcontrol.Turn` 管理每轮操作、确认及目标。`NewAssistantConversation` 负责真实重置。已接收的 ACP 回调和 MCP 请求捕获不可变的轮次绑定；工具请求另捕获目标代次。旧输出、问题和工具调用不会重新绑定到下一轮或切换后的目标。

## 执行约束

### 页面重载与当前对话

当前对话的已接受问题、已收到回答及完成／失败／停止状态保留在应用进程内。页面重新载入先停止并等待旧轮次收尾，撤销其待答问题、批准和操作权，再恢复聊天显示；不自动续跑，不恢复待发队列或未发送草稿。部分回答保留原文，并显示实际结束状态。

新建对话同时清除模型上下文和显示记录；忙时明确拒绝。应用退出后不恢复这些记录，不把聊天内容写入审计文件或浏览器存储。后台显示历史最多保留 128 条消息、4 MiB 内容，按完整旧轮次移除；达到上限会提示较早消息已省略，模型仍可能保留相应上下文。

`pkg/assistantcontrol.History` 保存显示记录，不保存授权；`RestoreAssistantConversation` 负责旧轮次撤销、收尾等待及快照；前端只恢复消息。恢复失败时禁止发送，并提供重试或显式新建入口。重复恢复不追加历史记录。验证见 [助手稳定化基线](assistant-stabilization.md)。

### 工具执行

MCP 只监听 `127.0.0.1`，每段对话使用随机端口及随机令牌。令牌只认证受管进程的通信；执行权限来自当前轮次的工具绑定，空闲、已取消和已结束轮次没有应用操作权限。它拒绝浏览器 Origin、无认证请求、额外授权参数、未知工具和并发操作。Chrys 的 MCP 连接明确绕过 HTTP 代理。

Chrys 使用独立临时用户目录和宿主生成的配置，不加载用户其他 Agent 配置、自定义工具、子 Agent 或其他技能目录。启用原生本地 Shell、文件和搜索工具及应用导入的 Skill 包；默认保留 Chrys 审批，常规只读辅助判定由 Chrys 处理，需要确认的本地操作经 ACP 单次授权，界面明确执行位置。宿主工具继续由对应服务核验授权，不重复叠加 Chrys 弹窗。远程终端的批准在 `terminalcontrol.Access` 发生，打开已保存连接的确认由工作台适配层构造；本地工具不会授予远程工作台占用或批准。

模型密钥和 MCP 令牌以环境变量交给子进程，生成的配置只保存变量引用。第三方 stderr 不原样写日志。对话关闭时关闭 MCP、终止子进程并等待退出，再尝试清理临时目录；正常轮次结束仅撤销工具绑定。这是可信 Chrys 的工具配置边界，不是恶意本机程序的操作系统沙箱。
