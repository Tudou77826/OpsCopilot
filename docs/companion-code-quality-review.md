# 伙伴展示代码质量与架构审视

2026-10-14，检查微光v8接入、统一70%显示比例、浅深场景背景及日常动作调度。结论：变更可以保留，未引入新的业务层、数据迁移或动画框架；需要收敛的临时构建依赖与资源生成风险已经修正。

本文记录视觉与调度改动的审视。后续1–100级规则涉及Go快照和公开资料投影，其变更与验证范围见 [等级交付验收](companion-delivery.md#1100级成长验收)，不沿用本文“Go业务没有变更”的范围结论。

## 架构影响

展示、位移步幅与活动范围共用 `companionDisplayScale`。容器分配保持原生阶段比例，防止缩小角色后反而放大容器抵消缩放。该比例不进入个人存档、经验结算或公开资料。

微光通过已有内容契约声明单个落地接触帧，其他角色仍使用各自接触与收步片段。播放器只读取契约，不按角色名分支；继续复用帧边界定时与浏览器transform位移，没有加入骨骼、实时插帧或每帧Canvas处理。隐藏、收起和减少动态效果仍停止调度。

场景通过主题CSS变量选取两张WebP。助手、设置和公开资料共用主题入口；没有另建主题监听、React状态或服务请求。两张背景合计48,028字节。微光从96帧缩至88帧，正式PNG由4,920,467降至4,543,665字节，其他六包没有重绘。

Go业务、Wails/Teams数据接口、成长规则、奖章统计、排名及同步队列没有变更。角色素材仍与业务状态分离，存档中的角色ID和阶段继续兼容。

## 验证范围

共享伙伴测试49项、素材与工具测试26项通过；共享前端、桌面与Teams类型检查和构建通过。构建器调整后90个正式文件逐字节重建一致。

34115实际产品页自然观察44秒，未触发环境动作，点击后正常回应；存档保持一致，无页面异常，见 [自然待机记录](assets/companion-quality-calm/result.json)。完整动作专项覆盖左右行走、回正、点击回应、舒展、主题、缩放、窄窗口、收起和减少动态效果，见 [行为记录](assets/companion-quality-behavior/result.json)。专项缩短环境等待，不作为日常频率或性能基准。

## 保留的限制

微光的招呼与开心共用同一组耳部回应，仅停留节奏不同。起步与停步来自已有转身、落地姿态的人工选择；这是素材生产质量限制，公共端点相同不能证明全部邻帧自然。后续应优先完善独立过渡素材和完整动作视觉验收，避免用更复杂的运行时逻辑补偿不合适的原稿。

历史素材包仍保留，构建门禁会验证全部历史包；生成脚本还有按具体原稿选择腾空区间和观察顺序的固定参数。当前没有扩散到业务或播放器，后续素材规模增长时可整理生成规格与历史包归档。候选发布以验证通过后复制文件实现，并非文件系统事务；构建与素材生成应顺序执行，正式应用继续消费已完成门禁的dist产物。
