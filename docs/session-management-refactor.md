# 会话管理重构

> 范围：已保存连接的信息管理与文件夹层级，以及 Xshell 会话导入。
> 状态：已实现并完成实机验收。

## 一、背景与目标

会话管理此前能跑通增删改连，但存在一组结构性缺陷，其中一部分已在真实数据上产生可见偏差：

| 缺陷 | 表现 |
| --- | --- |
| 文件夹按**名字**寻址 | 重命名文件夹后，其子会话的分组字段与实际位置失配 |
| `config.group` 与树结构是**两个真相源** | 真实 `sessions.json` 中，`测试设备(演示)` 文件夹下的 3 个会话 `group` 全为空 |
| 递归结构实际只支持**单层** | 数据模型与前端渲染都支持嵌套，但后端所有分组查找只遍历根级 |
| 没有排序持久化 | 前端每 5 秒轮询并按字母序重排，用户在拖拽里表达的顺序会被下一次刷新抹掉 |
| 落盘非原子 | 全量覆写 `sessions.json`，写入中途崩溃即产生截断文件 |

重构目标有两条：清掉这组技术债；把文件夹管理补到能与 Xshell 对标的程度，并支持把 Xshell 的会话导出导入进来。

## 二、数据模型

持久化格式保持不变，旧文件零迁移可读：

```go
type Kind string
const (
    KindFolder     Kind = "folder"
    KindConnection Kind = "session" // 取值沿用历史 JSON 的 "session"
)

type Node struct {
    ID       string                `json:"id"`
    Name     string                `json:"name"`
    Type     Kind                  `json:"type"`
    Children []*Node               `json:"children,omitempty"`
    Config   *remote.ConnectConfig `json:"config,omitempty"`
}
```

三条不变量：

1. **树结构是归属的唯一真相。** `config.group` 降级为写时派生的单向镜像（根为空，否则为直接父文件夹名），仅为兼容 `pkg/core/ops` 等外部消费者而保留，不参与任何判断。
2. **文件夹按 ID 寻址。** 重命名文件夹不再使任何引用失配。
3. **嵌套深度不限。** 移动操作做环检测，禁止把文件夹移入自身或其后代。

`config.group` 只做镜像带来一个设计取舍：嵌套场景下同名文件夹位于不同层级时，该字段无法表达完整路径。它只被当作展示提示使用，因此接受这一歧义。

## 三、持久化

- 落盘改用 `internal/atomicfile`（临时文件 + `fsync` + `rename`），并收敛了仓库里另两处同模式的重复实现。
- `Load()` 后执行一次**对账**（`reconcile`）：补全缺失 ID、为重复 ID 重新分配、纠正互斥字段（文件夹不应有 `Config`、连接不应有 `Children`）、补齐空名称、按结构重建 `group` 镜像。该操作幂等。
- 对账产生变更时，**先备份**为 `sessions.json.bak-<时间戳>` 再落盘，用户可回退。
- 内容与上次写入完全相同时跳过写盘。因此日常操作不会累积备份，也不会无谓刷新文件时间戳。

验证方式：以重构前的真实 `sessions.json` 为样本，对账后**层级、名称、顺序逐项不变**，仅漂移的 `group` 被修正，且生成一个备份；二次加载不再产生变更与备份。

## 四、接口

`pkg/sessionmanager` 更名为 `pkg/connectionstore`，`Session` 更名为 `Node`，与 `pkg/session`（运行态连接）的同名歧义消除。文件夹相关操作全部改为 ID 寻址：

```go
Snapshot() []*Node                    // 深拷贝，不再暴露内部切片
CreateFolder(name, parentID string) (*Node, error)
CreateConnection(cfg, parentID string) (*Node, error)   // 新建连接但不建立会话
RenameNode(id, name string) error
UpdateConnection(id string, cfg) error                  // 位置不变
MoveNode(id, newParentID string, index int) error       // 移动 + 同级排序 + 环检测
ReorderNodes(parentID string, orderedIDs []string) error
DeleteNode(id string) error
DuplicateConnection(id string) (*Node, error)
EnsureFolderByNamePath(path string) (string, error)     // "A/B" 形式，连接时"保存到分组"用
FindByEndpoint(protocol, host string, port int) *Node
```

Wails 边界改用 `(T, error)` 返回约定，前端不再依赖"返回串里是否含某段文案"来判断成败。驼峰与下划线两套结构的转换统一收敛到一个转换函数，避免逐处重复实现漏掉字段。

排序规则由前端计算后经 `ReorderNodes` 落库：浏览器的 `localeCompare('zh-CN')` 能正确处理中文拼音序，Go 侧没有等价的本地化比较。

sidecar 复用同一套 `connectionstore`，并补齐了此前缺失的复制能力，两端方法集与语义一致。

## 五、界面行为

- **多层嵌套与拖拽排序**：按行高三分区落点——上 25% 插到该行之前、下 25% 之后（同级排序），中间 50% 且目标是文件夹则移入。文件夹自身可拖；环检测在前端拦下并显示禁止光标，后端另有独立校验兜底。原地不动的移动直接跳过，不产生写盘。
- **拖拽环境**：悬停文件夹 600 ms 自动展开；拖到列表上下边缘时自动滚动（长列表下底部的会话需要能拖到顶部的文件夹）。
- **展开态持久化**，搜索时自动展开命中项的祖先链；深层节点不再继续缩进，改用完整路径提示。
- **删除文件夹前提示会连带删除多少个连接。**
- **新建连接（不建立会话）**：补上了此前只能"先连接再自动落库"的缺口。
- 连接属性弹窗不再提供自由文本"分组"输入：归属只由树里的位置决定，从根上消除字段值与实际位置不一致的可能。
- 移除了 5 秒轮询与客户端的字母序重排，改为变更后刷新 + 窗口重新聚焦时刷新。

## 六、Xshell 导入

### 输入形态

三种输入共用一套解析：单个 `.xsh` 文件、包含 `.xsh` 的目录树（子目录即分组）、`.xts` 备份包（ZIP，内含 `xts.zcf` 与 `Xshell/<分组路径>/<会话>.xsh`）。

同机场景下优先使用**自动探测本机会话目录**（`%USERPROFILE%\Documents\NetSarang Computer\<版本>\Xshell\Sessions`，兼容 OneDrive 重定向）。这条路径不需要用户做任何 Xshell 导出操作，也不需要解包。

### 编码

`.xsh` 与 `.xshf` 实测为 UTF-16LE with BOM；中文环境的旧版本写 GBK；ASCII 与 UTF-8 原样通过。解码按 BOM → UTF-16LE/BE → 合法 UTF-8 → GBK 回退依次判定。ZIP 成员名同样按原始字节重新解码——中文环境下 Xshell 写成员名用 GBK 且不置 UTF-8 标志位。

### 密码解密

`.xsh` 的 `Password` 是 `Base64(RC4密文 ‖ SHA256(明文)[32])`。RC4 密钥按版本派生：

| Xshell 版本 | RC4 密钥 |
| --- | --- |
| < 5.1 | `MD5("!X@s#h$e%l^l&")` |
| 5.1 – 5.2 | `SHA256(SID)` |
| 5.3 – 7.0 | `SHA256(Windows账户名 + SID)` |
| 7.1+ / 8.x | `SHA256(reverse(SID) + Windows账户名)` |
| 启用主密码 | `SHA256(主密码)` |

实现不按版本硬编码单条规则，而是**枚举候选密钥并用密文尾部的 SHA256 校验和判定**。原因是各开源实现对 8.x 的描述互相矛盾（多数资料仍写作 `Windows账户名 + SID`），而校验和让判定成为确定性判断——错误密钥通过校验的概率是 2⁻²⁵⁶。实机核对确认本机 Xshell 8.1 走的是 `reverse(SID) + Windows账户名`。

两个容易踩错的点：

- 密钥里的账户名是 **Windows 账户名**（如 `15802`），不是会话里的 SSH 登录名（如 `root`）。用后者代入必然解不开。
- SID 与账户名由 `os/user.Current().Uid` 与 `USERNAME` 取得，无需 cgo 或 advapi32。

### 同机约束

Xshell 5.3+ 的密码密钥依赖导出那台机器的 Windows 账户标识。**跨机器导入必须由用户提供源机器 SID 或 Xshell 主密码，否则密码在密码学上不可解**——这是密钥派生方式决定的，实现无法绕过。因此解密失败时不会静默留空：非敏感字段照常导入，报告明确说明原因，界面提供补充凭据后重新分析的入口。

### 合并策略

- 落点：合并到根层级，Xshell 的分组路径 `A/B` 逐层映射为嵌套文件夹，同名则合并。
- 冲突：按 `(协议, 主机, 端口)` 已存在则跳过并计入报告。导入是补齐而非覆盖，不改动用户已有会话的任何字段。
- 先分析后写入：分析阶段只读，报告将导入数、已存在数、密码可解密数。这样用户在写入前就能发现密码解不开，而不是导完才发现。
- 不支持项明确跳过并告警：非 SSH/Telnet 协议；使用 `UserKey` 密钥认证的会话（当前仅支持密码认证）；引用外部代理定义的跳板配置。

实机过程中发现并修复了一个缺陷：点击「分析并预览」后整个界面黑屏。根因在边界契约——Go 的 nil 切片与 nil 映射序列化为 `null` 而不是 `[]`/`{}`，前端按数组/对象处理即抛渲染异常，而 React 的渲染异常会卸载整棵组件树，表现就是整个应用黑屏。修复分两层：导入结果里的集合字段一律返回空集合（契约），前端对这两个字段做容错，并新增渲染错误边界把"一处出错全盘不可用"降级为"局部降级可重试"。回归用例用后端真实返回的形状（`warnings: null`）构造，在此之前该形状没有被任何用例覆盖。

## 八、已知边界

1. **跨机器导入密码**：没有源机器 SID 或主密码时不可解。界面明确告知原因并提供补充凭据入口，不假装成功。
2. **`.xts` 主密码加密包**：`xts.zcf` 的 `Master=1` 表示整包被主密码加密，Go 标准库无法读取。此时提示改走本机会话目录。若实际使用中确有此需求，再评估引入支持加密 ZIP 的第三方库。
3. **密钥认证**：`UserKey` 认证的会话导入主机与用户名后会告警，需要手工补充密码。
4. **代理/跳板**：Xshell 的代理定义是独立文件，不随会话导出，因此只告警不做映射，避免让用户误以为是直连。
5. **`config.group` 在嵌套下的歧义**：同名文件夹位于不同层级时该镜像无法表达完整路径。它只作展示提示。
