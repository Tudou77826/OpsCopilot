# AI 数据库工作区试用

## 使用方式

用户可以让助手使用已保存的数据库配置，或新建并保存连接。新建时，助手预填已知信息，用户在正常连接面板补全密码并保存；模型只收到保存后的配置编号和公开连接信息。沿用已导入的 JDBC 驱动、JRE 运行组件及已保存的 SSH 连接。

助手打开独立、完整的数据库工作区，使用新的物理会话，不继承人工页签中的事务。工作区复用现有对象树、查询编辑器、表数据、结构、结果和查询页签功能。助手释放控制权后，用户在原位置继续编辑和查询。

聊天不占用工作区。模型通过 `database_take` 和 `database_release` 明确控制占用；占用时显示遮罩和页签标记，物理会话的人工查询、断开和相关配置编辑也由后端阻止。另一个物理会话可以继续使用同一配置。

## SQL 与交接

- 每次模型提交必须包含用途和一条 SQL。每条记录有独立编号，查询区追加时间和用途注释及原始 SQL，只执行本次新增块。
- 重试或修订需要追加新记录，同一记录不能再次提交。失败、拒绝和取消的记录仍保留原文和状态。
- “AI 执行记录”可以查看各块原文及结果。用户可编辑查询区；独立记录保留模型最初提交的 SQL。
- 首次接管确认本次读取与常规查询范围。简单 SELECT 可自动继续；写入、敏感标识、未知函数和其他无法可靠判断的语法逐次确认。该分类是保守筛选，不能证明任意 SQL、视图或数据库函数没有副作用。
- 停止、手动接管和轮次结束撤销占用。运行中的 SQL 通过既有驱动取消机制处理；驱动可能因此断开会话，界面据实际结果显示状态。
- 关闭运行连接需要当前控制权和单独确认，不主动提交事务。未提交事务可能回滚；保存的配置、SQL 和已有结果保留。交还后的连接需要重新取得控制权才能关闭。

配置按现有方式保存，密码进入系统凭据库。工作区文档与结果目前驻留应用进程，不提供跨进程恢复。关闭整个工作区会结束相应会话；不删除保存的连接配置。

## 实现边界

| 层 | 职责 |
|---|---|
| `pkg/dbworkspace` | 既有连接、JDBC、SSH、查询与取消；新增物理会话占用检查及获批配置版本核验 |
| `pkg/dbcontrol` | 独立工作区、实际呈现回执、占用、追加记录与执行审计 |
| `pkg/assistanttools` | 每轮数据库工具、授权与精确 SQL 确认；复用单 AI 串行调度 |
| `pkg/agenttransport/mcp` | 参数契约与工具适配，不接受密码、任意物理会话编号或占用凭据 |
| 桌面适配器与共享数据库界面 | 正常连接表单、完整工作区、结果展示、人工接续和占用遮罩 |

工具包括配置/工作区列表、新建配置、打开独立工作区、接管、读取现场、表列表、表结构、追加执行、释放和关闭连接。没有提供删除保存配置的模型工具。

打开、接管和每次执行前，宿主等待当前页面确认实际选中工作区及真实编辑器内容；页面未呈现、停止后的旧调用和旧审批不能继续执行。模型接收有大小上限的观察，完整结果留在正常界面。

执行前写入审计意图，之后记录结果状态；元数据读取和关闭意图也有记录。文件位于配置目录的 `audit/database/executions.jsonl`，保存关联编号、阶段和 SQL 摘要，不保存 SQL 字面量或密码。审计写入失败时禁止继续提交；结果审计失败会提示可能已执行，不能自动重试。目前文件上限为 16 MiB，自动归档和审计查看界面留待稳定化阶段。

## 本地稳定性收尾

停止和释放后的操作权不能继续读取、发送 SQL 或关闭已交还的连接。接管途中取消不会发布新的占用；取消前尚未发送的 JDBC 请求不再进入传输。取消处理覆盖数据库选择、元数据读取和 SQL 执行阶段，失效物理会话按实例回收，保留查询文档及已观察到的执行结果。

模型释放控制权不改变事务状态。同一工作区内复制查询仅复制文本，继续使用该工作区的物理会话和事务；不会自动执行复制的 SQL。不同工作区的独立物理会话不共享事务。关闭连接不主动提交；取消长查询可能断开连接，人工可重新连接后继续使用保留的查询区。

取消断开或重连后停止后续流程，继续显示原会话配置；配置已经保存时明确提示新配置需要重连才生效。旧查询的迟到成功或错误不能覆盖新物理会话的查询，AI 的迟到结果也不能覆盖交还后人工发起的结果。重新连接使用新的物理会话，不复用已经取消的会话编号。

执行结果与审计失败分别处理：已观察到 SQL 成功时，后续审计错误保留该执行结果并停止自动操作，不能改写成“SQL 未执行”后再次提交。断开运行连接保留文档和结果；显式关闭整个工作区后回收对应的内存记录，后续轮询不再复制已关闭文档。

## 验证范围

2026-10-21 在隔离 MySQL 8.4.8、导入的 Connector/J 9.7 和私有 JRE 上，通过真实 Wails、Chrys ACP、MCP 及真实模型完成以下流程：

1. 新建保存配置，密码由正常连接面板填写。
2. 创建独立完整工作区，接管后人工直接调用查询接口也被阻止。
3. 同一配置另开独立会话，人工查询不受影响。
4. 两次追加带用途的 SQL，审计逐项匹配新增原文摘要，没有重放前文。
5. 释放后人工在同一查询区追加并执行第三条查询。
6. 新轮次重新授权并确认关闭运行连接，保留配置、原文和结果。

结果记录：`e2e/.runtime/handoff-desktop-1792565500887/result.json`，七项检查通过，无页面异常。确定性模型使用同一真实 ACP/JDBC 路径作补充回归；包级测试覆盖占用入口、取消、审批拒绝、审计失败、配置版本变化及重复提交；共享数据库界面测试覆盖接续使用。

稳定性回归记录：`e2e/.runtime/handoff-desktop-1792555272285/result.json`，使用确定性本地模型、真实 Chrys ACP/Wails/JDBC 和隔离 MySQL，12 项检查通过，无页面异常。在上述基础链路之外，验证了未提交事务交还、复制查询后人工回滚、确认关闭后未提交写入不可见、停止后的旧审批失效、长查询期间手动接管、服务器查询结束，以及取消后重新连接并继续查询。

数据库前端的连接面板、完整工作区和会话生命周期共 40 项测试通过。后端定向测试与 `go vet` 通过；取消、旧操作权、交接、已执行结果的审计异常等关键用例连续运行 20 轮通过。当前 Windows 环境未启用 CGO、也没有可用 C 编译器，未运行 Go 竞态检测；重复运行不替代竞态检测。未执行可能访问既有业务环境的全仓测试。

本地稳定性收尾已完成，不能据此宣称 Gauss 100、内网跳板链、其他驱动的取消及事务语义均已验证。目标环境验收、审计归档和整体性能基线保留在后续稳定化工作中。阶段 5 的业务环境动作尚未实施，需另行讨论。本次没有更改 CLI。
