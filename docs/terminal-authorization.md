# 终端授权、审批与实际执行审计

桌面助手的现行决策规则见[桌面助手的操作审批](assistant-authorization.md)。本文的字面只读子集和一次性审批描述基础接口；桌面入口通过 `RequireActionReview` 检查每条命令的任务范围，再由宿主签发精确执行句柄。服务器 CLI 的策略不变。

状态：2026-10-20。本文说明授权和审计基础接口；第五批已接入[终端助手](assistant-terminal-trial.md)，通过受控 MCP 在原 SSH PTY 执行命令。基础接口默认保留早期固定体验的一次性审批流程，模型适配器显式启用下述连续占用模式。

## 统一调用路径

```text
可信应用协调器签发本轮 AccessScope
  → Access.Operations() 提供给调用适配器
  → 同一终端 Service / Run
  → 授权判断与发送意图审计
  → 在实际写入前再次核验连接、占用、账号和现场
  → 原有 SSH PTY
  → 保存提交与完成证据
```

`app_terminal_control.go` 的非导出工厂 `newTerminalAccess()` 负责应用装配：目标必须属于当前活动连接；节点和 SSH 登录账号取自应用实际连接配置，不能由工具调用参数覆盖；应用退出会使授权失效。授权使用本地文件审计，存于配置目录下 `audit/terminal/<随机标识>.jsonl`，单个授权文件上限 64 MiB。

`AccessScope` 由可信宿主根据用户授权构造，包含调用主体、期限、实际页签/连接 ID、允许的 Shell UID，以及允许自动读取的具体文件和列出的目录。构造时复制作用域，外部修改原切片不能扩大权限。作用域最多 128 个目标，期限不超过 24 小时；终端每轮仍遵循默认 30 秒、最长两分钟的运行期限。

适配器只拿到 `Access.Operations()`；`Approve()`、签发授权的工厂和底层 `Service` 保留在可信宿主内。`Service.Take()` 是底层可信接口，供装配与固定实验使用，不是可直接开放给 AI/插件的授权门面。当前没有新增任意命令 Wails、MCP 或 CLI 入口；这不是可隔离恶意进程内 Go 代码的沙箱。

## 自动继续与需要确认的边界

默认只识别很小的字面命令子集：`pwd`、`id`、`whoami`、`uname`、`uptime`、不带修改参数的 `date`，以及有限参数的 `ps`、`df`、`free`。`cat`、`head`、`tail` 和 `ls` 还要求目标为宿主明确授权的具体绝对路径，并满足限定参数格式。

宿主可在用户授权当前节点的常规排查后设置 `AccessTarget.RoutineDiagnostics`，允许普通路径上的字面量 `ls`、`cat`、有限 `head` / `tail` / `grep`，相对路径按实际 Shell 目录判断。不允许凭据路径、`/proc` / `/sys` / `/dev`、持续读取、管道或未知选项借此自动通过；模型不能通过工具参数设置该能力。快速分类提供类别、影响与确认原因，未知不等于已确认危险。此能力仍不识别符号链接最终目标或正文中的秘密，须在受信任的节点和排查授权范围内使用。

未识别的命令、组合命令、重定向、命令替换、通配符、脚本解释器、修改操作以及敏感路径，一律进入明确审批。不是简单匹配命令开头，也不接受模型自述的“只读”或 `approved=true`。既有 CLI 白名单保持原行为，不被当作新的自动放行依据。

这项分类控制软件的自动发令，不证明远端 Shell 或命令程序可信。它不解析完整 Shell 语言，不解析符号链接，也不识别文件正文中的秘密。宿主只能把已经明确授权查看的文件内容加入 `ReadFiles`；来源、链接目标或敏感性不明确时不授予自动读取。涉及通配日志、复杂管道和更多运维工具的自动分类，后续在对应语义与回归到位后扩展，不能通过加宽前缀规则代替。

## 审批与交接

模型的连续操作使用宿主构造的 `TakeRequest.RetainOnApproval`：待批时保留同一 Run 和租用，阻止人工输入及其他命令；批准只允许原命令执行一次，执行完仍保留占用，直到模型显式释放。审批不能重建已经停止、过期、释放或换连接的 Run；身份或现场变化仍使批准失效。审批取消、执行错误及用户接管交还终端。以下默认一次性流程继续服务于原固定体验，不代表 AI 入口的占用策略。

敏感或无法确认的命令返回 `ApprovalRequired`，原运行进入 `awaiting_approval` 并交还终端。宿主通过 `Review()` 获取原始命令和目标现场供用户确认；这些原始内容不写入审计。等待期间没有可继续发令的旧运行。

用户明确批准后，宿主调用 `Approve()` 得到不透明、一次性的 `ApprovedOperation`。批准本身不执行命令；执行句柄的 `Execute(ctx)` 不接收命令、地址、账号或参数覆盖，因此只能执行原操作。新执行轮次通过审批 ID 与原操作关联，完成后自动交还。

审批绑定原实际连接、原运行、命令与参数、Shell PID、UID、目录、退出状态及提示符序号。批准前、重新接手时、持久化发送意图后和实际写入前均会核验。用户操作产生新提示符、切换账号、重连，或期间已开始另一轮接手时，旧审批不能继续。现场未知时直接拒绝，不因旧批准重新向未知程序发送初始化命令。

待批项最多保留一分钟，且不超出授权期限；最多保存 128 项。调用方取消、宿主撤销授权、对原待批轮次明确停止、超时、拒绝或重复使用均不能发令。后续 ACP 适配器必须把用户停止和“立即发送”绑定到整个 `Access.Cancel()`，不能只停止已经释放的底层运行，也不能在等待审批时取消并丢弃其所属任务上下文后继续使用批准。

## 实际执行证据

审计与生命周期调试日志分开，记录调用主体、实际连接 ID、节点、SSH 登录账号、Shell UID/PID、运行/操作/审批 ID、时间、授权依据、提交状态、完成状态和确认的退出码。目录和命令保存 SHA-256 指纹，命令另记字节数；不保存原始命令、目录正文、终端输出、凭据或任意驱动错误文本。指纹用于关联，不是加密或脱敏后的完整命令回放。

| 事件 | 可以证明的事实 |
|---|---|
| `context_read` | 获准返回一份有限现场快照，不记录正文 |
| `approval_required` / `approval_granted` / `approval_denied` | 本机审批决策及关联操作，不代表已经执行 |
| `dispatch_intent` | 发送前审计已持久化，尚不能证明字节已发送 |
| `authority_revoked` | 本轮操作权已撤销，不代表远端程序已终止 |
| `result` | 实际观察到的 `Submission`、`Completion` 和可确认退出码 |

本地写入仍遵循[终端接口结果语义](terminal-operations.md)：完整写入不等于完成；部分写入、取消或断连可能只有未知结果，不自动重试。阻塞写入尚未返回时可以先记录撤权，迟到返回后再补结果。交还后的新输出不会进入旧结果。

审计在锁外执行，逐条追加并同步文件。发送前不能保存审计就不发送；结果保存失败会保留返回值中已确认的执行证据、撤销整份授权并停止后续发令，不能当作“未执行”重试。达到上限、文件不可用或发现末尾写入不完整时停止，不静默覆盖历史。文件系统 I/O 仍可能阻塞；本机操作权先撤销，停止请求的响应可能等待审计 I/O 返回。

文件按 `0600` 请求创建，Windows 使用所在目录的访问控制。当前没有防篡改存储、跨进程追加协调、审计检索页面、自动归档或总目录配额治理；宿主为每份授权使用独立随机文件避免共享追加冲突。原始终端录制仍是另一项显式功能。

## 验证与剩余工作

相关 Go 包及桌面终端回归各五轮、静态检查通过；新增测试覆盖范围和身份拒绝、审批等待释放、一次性执行、停止/取消/过期/换连接/换现场失效、写入前再核验、审计失败、阻塞写入撤权证据、结果保真、敏感内容不落盘，以及审计上限和不完整文件拒绝。

本机 ash、Bash 各三轮验证了自动只读、明确批准后在原 Shell 执行一次、人工操作改变现场后拒绝旧批准，以及审计文件持久化；每条链路只用一个 SSH 会话，没有额外 exec。PTY 日志为忽略目录中的 `e2e/.runtime/terminal-access-pty.log`。这些结果不代替目标内网验收，未运行 Windows Go 竞态检测。

原有完整页面八项交接检查通过，页面脚本错误为零；证据为 `e2e/.runtime/handoff-desktop-1792480564366/result.json`，日志为 `e2e/.runtime/terminal-access-e2e.log`。页面仍是固定测试，未验证尚未实现的审批卡片。Wails 开发模式仍有 `runtime:ready` 与 WebSocket 退出日志，不将页面脚本错误为零解释为后端无日志。
