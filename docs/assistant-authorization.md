# 桌面助手的操作审批

助手使用 iCode 的 `auto` 模式审查工具调用。iCode 自动通过的操作继续执行；iCode 请求确认时，OpsCopilot 展示请求和审查原因，用户拒绝、停止或关闭请求均不能转为批准。OpsCopilot 不再启动独立的模型审查或隔离审查会话。

## Ops 执行入口的兜底

- 远程终端：对明确的删除、服务或权限变更、敏感凭据访问、覆盖重定向等操作要求人工确认。命令仍绑定实际连接、身份、终端现场和一次性执行权。
- 数据库：对识别出的数据或结构修改、敏感访问以及可能回滚事务的连接关闭要求确认。每条 SQL 保留在独立的查询块中。
- 文件传输：上传因无法保证远端不被覆盖而需确认；覆盖本地目标或访问识别出的敏感路径需确认。自动下载使用不覆盖发布，不能安全发布时失败。

兜底规则只覆盖能够识别的风险，并非完整的 Shell 或 SQL 安全解析器。iCode 原生本机工具由 iCode 自身审查，不经过上述 Ops 执行入口。

## 生命周期与上下文

用户停止或手动接管后，本轮执行权失效；正在等待的确认不能在停止后批准。页签释放、连接身份、实际目标和审计仍由对应执行服务控制。

当前 iCode 审查模型主要接收本轮用户消息；新一轮只有“继续”时，较早轮次中的限制不一定进入审查模型。主对话模型仍有会话历史，但这不能保证审查覆盖了所有前文限制。

## 验证

`go test ./...` 覆盖代码层回归。设置 `OPSCOPILOT_CHRYS_TEST_EXE` 后，可运行 `TestLiveICodeAutoReviewsOpsToolAndForwardsRejection`，验证真实 iCode 进程下的自动审查和人工拒绝转发；模型和远程工具使用隔离模拟，不访问业务服务器。
