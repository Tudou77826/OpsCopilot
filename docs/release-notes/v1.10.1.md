# v1.10.1

## 新增：从 Xshell 导入快捷命令

- **一键导入本机 Xshell 的快捷按钮**：自动探测 `<版本>\Xshell\QuickButton Files` 目录，无需在 Xshell 里做任何导出操作。也可手动选择单个 `.qbl` 文件或包含 `.qbl` 的目录。
- **落点参考 OpsCopilot 现状**，而不是只看导入的东西：
  - 分组不再靠手打：点开集合分组或逐条分组就是全部现有分组，逐条另可选「跟随集合」，需要新分组时走「＋ 新建分组…」再输入。清单只在选择器里出现，不在别的页面重复列一遍。
  - 还没有任何快捷命令时，来源页说明"导入时会新建分组"。
  - 某套按钮里若有命令的内容已经存在于某个分组，**默认落点就取那个分组**——不会给本该进「普通运维」的命令凭空新建一个分组。
  - 逐条标出所在位置：分组、名称、内容都相同标「已存在」（会跳过）；只有内容相同（名称不同）标「已在某分组」，提示它其实已有对应命令，可取消勾选或改名称对齐。
- **导入前先看清会发生什么**：预览只给三个数字——将导入、已存在（跳过）、类型不支持（跳过），并随你的改动**实时**重算。
- **粒度到单条命令**，三层都可以改：
  - 集合级：勾选要导哪几套按钮；每套填一个默认分组。两套填成同一个名字即合并，填不同即分开。
  - 命令级：逐条勾选（含全选、全不选、收起展开）。类型不是「发送字符串」的按钮（脚本、菜单等）仍然列出来，但置灰加删除线并写明原因，不可勾选。
  - 字段级：逐条改名称、改命令内容；逐条覆盖目标分组（默认跟随所属集合），因此一套按钮可以拆到多个分组。
- **「已存在」按最终归属实时判定**：它取决于目标分组，所以改集合分组、改单条分组、改名或改内容之后会立即重算——换了分组就不再算重复。预览给出的数字与点下去实际写入的结果一致。
- **确认按钮带条数**：「确认导入 N 条」；一套都没勾选时禁用。
- **按钮多的导出不会糊成一片**：超过 8 条的集合默认收起（条数与落点提示仍在集合头上），展开后逐条列表有高度上限并内部滚动；没有按钮的集合直接说明"没有可导入的命令"，不再摆一个空列表和用不上的按钮。
- **分组命名由你定**：默认 `Xshell`，输入框旁实时提示是新建分组、追加到已有分组，还是与本批其它集合合并。因为分组本身不支持重命名，命名权放在写入之前。
- **重复导入是幂等的**：目标分组内已存在同名同内容的命令会被跳过并计入报告，重复导入同一份 `.qbl` 不会把命令库堆成重复项。

## 变更：快捷命令存储

- `quick_commands.json` 改为原子写入（临时文件 + 替换）。导入会一次性写入整个命令库，此前的直接覆写一旦中途失败会丢掉全部快捷命令。

## 修复：导入预览的行内条数显示为 0

- 预览中每个集合那一行显示成"可导入 1 / 共 0 条"。该行的按钮数没有被填值，界面统计卡片上的总数却是对的，因此两个数字互相矛盾。

## 修复：导入完成后看不到结果报告

- 导入成功后弹窗跳回来源步，用户只看到一条提示，看不到本次写入了什么、跳过了多少。原因是弹窗的流程重置依赖宿主适配器对象，而该对象会随外层渲染被重建，导入触发的状态更新正好触发了这次重建。

## 重构

- `pkg/sessionimport` 更名为 `pkg/xshellimport`。该包现在同时承载会话（`.xsh` / `.xts`）与快捷命令（`.qbl`）两类 Xshell 落盘格式的解析，原名与会话绑定，已不准确。
- 会话导入与快捷命令导入共用的对话框外壳、分区、统计卡片与提示列表抽到 `ui/common/ImportParts.tsx`，两处不再各写一遍。
- Xshell 数据目录的探测（`Documents` / `OneDrive\Documents` / `OneDrive\文档` 三种根目录）抽成共用实现，会话目录与快捷按钮目录共用同一套枚举与版本排序；根目录作为入参，目录探测逻辑现在可以脱离真实用户目录被测试。

## 新增：文件夹整体上传 / 下载

- **目录不再是"只能逐个文件传"**：会话树、文件面板中对目录右键或批量选中即可整树上/下行，目录行也支持拖拽发起传输。
- **目标已存在同名目录 → 默认合并**：目录并入、同名文件覆盖，发起前一次性确认，树内不再逐个弹窗；目标侧独有的文件保留不动。
- **范围与边界**：空目录保留；本地符号链接跳过（防环）；深度上限 40 层；不保留权限/mtime/属主，落目标侧默认属性（与单文件行为一致）。
- **三种传输模式全覆盖**：SFTP 直连逐文件落位；Root 中转整树一次中转后复制落位（中转阶段任一失败即中止、不动目标）；跳板机 Base64 直传逐文件传输并预扫描单文件 10MB 上限——超限时一次性列出全部超限文件整体拒绝，不传输任何字节。
- **失败不中断整批**：单文件失败收集清单继续传，完成消息带成功/失败统计与失败明细（最多列出 10 条）。
- **顺带修复单文件下载**：单文件下载的任务参数次序错位（历史遗留），此前表现为进度总量错误、目录下载直接报"文件不存在"，已修复。

## 新增：文件传输与批量操作的体验

- **Base64 直传上限 300KB → 10MB**：跳板机场景下大文件不再被挡；分块进度节流上报，进度条不再刷屏。
- **传输方式说人话**：完成消息与面板标签改为「SFTP · Root 直连」「Base64 直传（Root 提权）」等用户可读文案，不再统一显示内部代号 `sftp(root-relay)`。
- **批量覆盖确认支持「全部覆盖」**：批量上传/下载遇同名冲突时，确认弹窗新增「全部覆盖（本次剩余文件不再询问）」勾选，勾选后本批剩余冲突直接覆盖；作用域严格限定单批，上一批的决定不会泄漏到后续操作，单文件确认交互不变。
- **跳板机提权校验**：su 提权后严格校验 `id -u` 返回 0，密码错/PAM 拒绝时明确报错，不再静默以普通用户身份继续（此前会形成"列表打不开 root 目录、上传文件属主却是 root"的权限不一致，#75）。

## 修复：会话改名与分组被"自动还原"

- **根除一个顽疾**：用户改了连接名/分组名后，重连或复制标签会把旧名字、旧分组"还原"回来；极端时改完分组名发起全部连接，只有一个连接留在新分组，其余全部回到按旧分组名重建的文件夹里。
- **根因**：连接成功后的自动落库按"端点"整节点重写，并按配置里的分组名解析/新建文件夹，而重连重放的是连接当时捕获的旧配置。
- **修复**：自动落库改为 ensure 语义——同端点已存在时只合入本次拨号验证过的凭据（密码轮转能学进来；账号不同或凭据为空不合入，杜绝跨账号串密码），显示名与位置一律不动；树的归属与命名只有显式的重命名/移动/编辑操作可以改变，任何重连重放都不再改写树结构。

## 修复：智能分析（新建连接）

- **telnet 识别结果被丢弃**：AI 即使正确识别出 telnet，配置转换层也会丢掉协议字段，按 SSH 连 23 端口必然连不上。已透传协议字段（含跳板机），并归一化大小写、过滤未知协议值。
- **凭据解析更稳**：解析提示词明确"凭据可含特殊字符，原样保留"，并给出示例——`60.60.33.44 accon@123 passww_123` 中 `accon@123` 是完整用户名（不再被拆成 accon/123），`root@192.168.1.5` 这类登录身份串仍正确拆分。

## 已知边界

- 只支持"发送字符串"类型的按钮。Xshell 的脚本、菜单、带参数提示等类型在 OpsCopilot 没有对应能力，导入时置灰不可选，并列出原始类型值，不做猜测性映射。
- 命令内容原样写入。Xshell 快捷按钮中可能包含 `$app` 这类变量，能否解析取决于目标服务器的 shell 环境；在导入面板里改了内容就是改了，不会做变量展开。
- `.qbl` 文件里没有集合的显示名，分组名无法从文件恢复，因此默认值是 `Xshell` 而不是文件名，并可在导入时修改。
- 暂不支持从 `.xts` 备份包内提取 `.qbl`，也不支持把快捷命令导出回 Xshell。
- 导入的快捷命令只进入命令库，不会自动执行。
- SCP 降级模式不支持文件夹传输（无建目录/列目录能力），会明确报不支持。
