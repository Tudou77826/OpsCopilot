# OpsCopilot 内网服务中心设计

## 1. 目标与范围

部署一个内网可访问、能够访问 GitHub 的服务，为 OpsCopilot 提供产品门户、更新镜像、公告、用户反馈和经用户授权的运营统计。

首期同步 GitHub 最新正式版本，保留历史安装包；不提供发布暂停、推荐版本管理。团队配置分发、共享知识服务和 AI 请求中转作为后续独立需求。

本文定义首期功能与验收要求。实现入口为 `cmd/service-center`，部署和接入说明见 [内网服务中心部署与验收](intranet-service-deployment.md)。

## 2. 服务端与客户端职责

| 功能 | 服务端提供 | 客户端提供 | 本体改动 |
|---|---|---|---|
| 产品与帮助门户 | 产品介绍、下载入口、快速上手、常见问题、更新日志 | 快捷打开介绍页与帮助页 | 增加入口 |
| 内网自动更新 | 同步正式版本、缓存安装包及更新说明，提供内网查询和下载 | 查询版本、展示更新说明、下载和安装 | 更新来源改为可配置的内网服务 |
| 历史版本下载 | 历史安装包与更新说明 | 通过网页手工下载 | 无独立改动 |
| 快捷反馈 | 网页表单、反馈编号、处理状态与回复；管理员处理页面 | 快捷打开反馈页，提交内容由用户确认 | 增加入口 |
| 底栏轮播公告 | 公告编辑、排序、有效期和详情链接 | 获取并缓存公告，底栏轮播，点击查看详情 | 新增公告组件 |
| 数据采集授权 | 提供采集说明及版本，校验授权信息 | 开屏先征求上报同意；拒绝后可另行接受最简方案，设置页可修改 | 新增授权机制 |
| 运营与升级统计 | 接收授权事件，展示活跃安装、版本分布、功能使用与升级结果 | 授权后采集和上报事件 | 新增采集与上报模块 |
| 服务运维 | 健康检查、同步状态、失败记录和存储监控 | 网络失败提示与必要缓存 | 调整失败处理 |

## 3. 服务边界与主要流程

服务端按门户、更新、公告、反馈、统计五个模块组织，首期统一部署；数据库保存业务记录，文件存储保存安装包。管理员经身份认证管理公告、反馈和查看统计。

- **更新**：服务端定期同步 GitHub 元数据和附件；安装包完整下载并校验后，才向客户端公布对应版本。客户端检查更新时先访问 GitHub，失败后访问已配置的内网服务，总等待时间约 10 秒；安装沿用检查成功的来源。服务端外网中断时继续提供已同步版本，支持管理员手工触发同步。
- **客户端接入**：统一配置服务地址，复用现有更新重试、断点续传和安装流程；镜像下载提供文件名、大小、校验值及 Range 支持，客户端安装前验证校验值。
- **公告**：仅展示有效期内的公告；无公告时收起轮播区域，获取失败时使用仍有效的缓存。公告内容限纯文本和受控链接。
- **反馈**：首期通过网页提交与查询，应用内不自动上传日志。附件由用户主动选择，页面提示检查敏感内容；反馈编号与查询凭证分开，防止枚举读取。
- **统计**：客户端计数、入队与发送均检查授权；服务端校验字段白名单、采集说明版本和记录编号，重复记录不重复计数。
- **共享功能**：共享知识库和共享连接信息由各自业务服务独立管理，不属于本服务的数据上报；其配置、权限与用户主动共享行为独立于统计开关。

## 4. 开屏授权与数据范围

### 4.1 用户授权

首次启动接入该服务的版本时，在任何打点发生前展示开屏弹窗，明确说明会收集哪些数据、采集目的、接收服务、保存期限和关闭方式。说明随客户端提供，离线也可查看。文案采用两层协商方式：第一层列出收集与不收集的内容，第二层提出更精简的方案，不以“已关闭”等状态陈述代替征求同意。两层明确说明：数据发送至内网服务器，不涉及任何形式的外发。

第一步提供两个同等清晰的选择，无预勾选：

| 选择 | 行为 |
|---|---|
| **同意上报** | 采集下述常规白名单中的每日计数、基础环境和升级结果 |
| **拒绝上报** | 立即保存完全关闭状态，停止采集并清空待发数据，再展示可选的最简方案 |

拒绝后的第二步提供 **同意最简上报** 和 **不上报任何数据**。只有另行明确同意最简方案后，才采集每日活跃标记、客户端版本，以及记录编号、随机安装标识、统计日期、说明版本、同意时间和上报模式；不采集操作系统与架构、连接计数、Ctrl+K 计数、快捷命令计数或升级结果。最简方案采用相同接收服务与保存期限。拒绝最简方案或关闭弹窗保持完全关闭，不重复挽留。

关闭弹窗按拒绝处理。拒绝不影响更新检查与下载、公告获取、门户访问及本地功能；这些必要请求不夹带统计数据。用户仍可主动打开网页提交反馈，提交内容另行确认，客户端不自动附带版本、系统信息或日志。

弹窗明确说明：**共享知识库和共享连接信息不属于数据上报，由各自业务功能独立管理，关闭上报不关闭这两项功能。**

- 默认状态为未授权；仅用户主动同意常规上报或最简方案并成功保存后，才开启采集。未授权或完全关闭期间不生成统计安装标识、不记录或缓存待补报数据，之后同意也不补采先前行为。
- 本地保存常规上报、最简上报或完全关闭的授权选择、说明版本及同意时间。常规说明版本为 3，版本 2 常规授权需重新同意；最简范围版本保持 2，既有最简授权保留。已有完全关闭选择保留。重启保留选择，不重复弹窗；设置页始终提供采集说明及开关。
- 切换为完全关闭后立即停止所有自动上报模块的采集、入队和发送，取消待发请求、清空计数及队列并移除统计安装标识；已送达数据按保存期限处理，关闭不自动删除历史记录。
- 对授权模式扩大字段范围、改变用途或接收方时，提高说明版本并重新开屏征求同意；确认前停止采集和上报并清空旧队列。完全关闭模式保留拒绝选择，不因说明更新再次弹窗。单纯文案修订不重复征求同意。

### 4.2 常规上报白名单

| 类别 | 允许字段与事件 |
|---|---|
| 公共字段 | 记录编号、随机安装标识、统计日期、客户端版本、操作系统类型及架构、采集说明版本、同意时间及上报模式 |
| 活跃情况 | 每个安装实例每日一次活跃标记，不记录每次启动时间 |
| 连接计数 | 每日用户主动发起连接的次数及成功次数；自动重连不增加发起次数，同一次连接最多计一次成功 |
| Ctrl+K 计数 | 每日通过 Ctrl+K 成功打开快捷命令面板的次数；忽略长按重复触发，不记录面板内输入 |
| 快捷命令计数 | 每日用户主动执行快捷命令的次数；预览、编辑、取消及自动重试不计数，不按具体命令细分 |
| 桌面操作 | 脚本执行、AI 定位、归档、上传、下载、命令生成的发起及完成/失败/取消次数；脚本创建成功次数 |
| 知识与命令 | 手动搜索次数、有匹配/无匹配次数、文档成功打开次数、生成命令发送次数 |
| CLI 入口 | exec、file 上传/下载、diagnose、knowledge list/search/read 调用及完成/失败次数 |
| CLI 策略与恢复 | 命令/目标/路径/大小限制拒绝次数；连接恢复尝试/成功/失败次数 |
| 升级情况 | 当前及目标版本、检查/下载/安装/新版本启动阶段、结果、固定错误分类、升级关联编号；不记录逐次操作时间和耗时 |

所有功能均只上报每日汇总，不发送逐次事件、耗时或操作时间。`usage` 使用固定键白名单，不允许自定义功能名称或自由文本。

- 脚本创建按保存成功计数，包括停止录制后保存与手动创建，不计编辑。脚本执行完成指回放流程结束。
- AI 定位完成指生成结果，不等同于故障解决。命令发送指填入终端，不等同于远程执行成功。
- 知识搜索按点击搜索或 Enter 确认计数，不按输入字符或自动加载计数；打开按内容读取成功计数。
- 文件传输按用户任务计数；目录子文件、传输降级与自动重试不重复增加任务次数。取消单列，失败不含已识别取消。
- CLI 使用同目录桌面配置和授权，不弹窗、不自动同意。无授权、最简授权或服务不可用时不增加功能计数。exec 根据真实执行结果分类，即使原 CLI 退出码为 0 而结果 success 为 false，也记为失败；不改变原输出或退出码。
- CLI 同步确认和发送各设 250ms 网络预算，统计失败不改变业务结果；本地文件事务使用操作系统锁。强制终止进程可能只有发起计数，无结果计数；不据此计算取消率。恢复成功表示连接重新建立，随后命令仍可能失败。

每日计数按安装实例、日期和客户端版本汇总，以累计值上报；服务端按记录编号幂等更新，重试不累加重复值。

随机安装标识仅用于区分安装实例，不使用账号、设备序列号或硬件指纹。安装量不等于人数；升级成功以新版本成功启动并上报为准。统计只代表同意采集的安装实例，不能据此推算全体用户。

**不采集**姓名、账号、主机名、服务器地址、连接名称、连接配置、文件路径及文件名、快捷命令名称与正文、Ctrl+K 输入内容、问题与回答正文、会话内容、知识文档、密码、令牌和原始错误文本。结果和错误分类使用固定枚举，拒绝任意字符串扩展。

用户主动提交的反馈独立于打点授权，提交前单独说明所发送的内容。更新、公告等必要请求不携带统计安装标识，也不转化为未授权运营统计；应用与代理访问日志不记录客户端 IP、查询参数、请求正文及用户标识，服务运维仅保留接口级错误和汇总指标。

安装实例每日计数和升级记录默认保存 90 天，按日汇总且不含安装标识的数据保存 1 年，服务运维日志保存 7 天；自动清理并限制管理员访问。期限变更同步更新采集说明。

## 5. 接口与运行约束

| 接口 | 用途 |
|---|---|
| `GET /api/v1/releases/latest` | 已完整同步的最新正式版本、更新说明、附件信息 |
| `GET /downloads/{version}/{filename}` | 内网安装包下载与断点续传 |
| `GET /api/v1/announcements` | 当前有效公告 |
| `GET /api/v1/telemetry-policy` | 当前采集说明与说明版本 |
| `POST /api/v1/events/batch` | 经授权的每日计数和升级记录批量上报 |
| `/`、`/help`、`/feedback` | 产品介绍、帮助和反馈网页 |
| `GET /healthz` | 服务健康检查 |

客户端访问支持 HTTPS，以及服务端明确启用的 HTTP；服务地址变更使原有采集授权失效。完全关闭模式不请求采集说明接口及上报接口；采集说明更新随客户端版本交付。任一已授权模式下，统计接口不可访问或说明版本无法确认时停止采集；已授权且说明仍有效的待发记录可限量缓存，最多 7 天、1,000 条，超出后丢弃最旧记录。上报失败不阻塞启动或核心操作。

同步失败保留上一完整版本，后台显示最后成功时间及失败原因。公告、统计和反馈故障相互隔离，不能导致安装包下载不可用。

## 6. 实施顺序与验收

1. **服务端基础**：完成门户、镜像同步与下载、公告和反馈管理、健康检查。
2. **客户端接入**：配置服务地址，接入更新，增加介绍页、反馈入口和底栏公告。
3. **授权与统计**：先完成开屏授权、设置页撤回及白名单约束，再启用事件采集与统计后台。

验收重点：

- 客户端无法访问外网时，仍能查询、下载并安装已同步版本；服务端外网中断不影响已有安装包下载。
- 未完整同步或校验失败的安装包不对外公布；客户端校验失败不安装。
- 公告按有效期展示；反馈可提交、查询及由管理员回复。
- 首次启动未选择、拒绝、关闭弹窗、授权保存失败时，均无统计采集、缓存或任何自动数据上报；拒绝不影响正常功能。
- 完全关闭时统计、升级结果、诊断日志和崩溃报告均无自动上报；共享知识库和共享连接信息仍按各自权限与业务设置运行。
- 常规与最简模式仅发送各自白名单字段；桌面功能及 CLI 计数符合定义，自动重连、按键重复和上报重试不造成重复计数。
- 切换为完全关闭后清空计数及队列且重启保持关闭；采集范围变更必须重新同意。
- 新版本启动才计为升级成功；后台明确标示统计覆盖范围。
- 老客户端通过手工安装或内部软件分发完成一次过渡升级，后续走内网自动更新。
